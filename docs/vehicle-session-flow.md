# 車両セッション（チェックイン→利用→チェックアウト）フロー 設計叩き台

ステータス: ドラフト（合意形成中）／最終更新: 2026-06-25
基盤: `docs/platform-design.md`（車両グローバルID §5）。連携: `parking-location-flow.md`, `notification-flow.md`。
関連方針: `構成A`。OCR/位置は端末側・単発イベント（Realtime不使用）。

> 2026-06-25 更新: QRを**ローテーション式トークン**に変更（§8 全面改訂）。再発行で旧QRを失効、ADMIN貼付確認(有効化)を追加、スキャンエラーを全種可視化、**ナンバープレートOCRの退避ルート**を追加。`vehicle_sessions` に打刻手段・GPS状態の列を追記（§1）。

## 0. 目的

車両の乗り込み〜返却を1つの**セッション**として記録し、状態（傷）・走行距離・位置・利用目的を残す。損傷の責任所在、オイル交換管理、免許携帯確認、運営の所在把握に使う。

---

## 1. ★セッションモデル（背骨）

チェックインとチェックアウトは1つの**車両セッション**の両端。

- **開く（チェックイン）**: 目的・開始オドメーター・開始位置・稼働前点検。
- **閉じる（チェックアウト）**: 稼働後点検・終了オドメーター・駐車位置（`parking-location-flow.md`）→ 運営通知。
- 効果: 走行距離の差分・稼働中の新規損傷・利用時間が自動算出。**運営マップ＝openなセッション一覧（今どの車が出ているか）**。

```sql
CREATE TABLE vehicle_sessions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  vehicle_id uuid NOT NULL REFERENCES vehicles(id),
  org_id uuid NOT NULL,                 -- 使用org（貸与中は借用org）
  recorded_by uuid,                     -- membership
  purpose text NOT NULL,                -- 'work' | 'move' | 'private'
  shift_id uuid,                        -- work時に紐付け（任意）
  authorized_by uuid,                   -- private時の承認者
  status text NOT NULL DEFAULT 'open',  -- 'open' | 'closed'
  started_at timestamptz, start_lat double precision, start_lng double precision, start_odometer integer,
  ended_at timestamptz,   end_lat double precision,   end_lng double precision,   end_odometer integer,
  start_method text DEFAULT 'qr',       -- 'qr' | 'plate_ocr' | 'manual'（出勤打刻手段。§8.5）
  end_method text DEFAULT 'qr',         -- 同上（退勤確定の手段）
  start_gps_status text,                -- 'captured' | 'denied' | 'unavailable'（§9）
  end_gps_status text                   -- 同上
);
CREATE INDEX ON vehicle_sessions (vehicle_id, started_at DESC);
CREATE INDEX ON vehicle_sessions (org_id, status);
```

## 2. チェックイン フロー

```
「稼働開始」ボタン（=既定で「稼働」。目的ピッカーは置かない）
→ 車両QR読み取り（§8、+位置記録 → 運営マップに「乗り込み」表示。QR不可時はナンバープレートOCR §8.5）
→ 免許携帯確認（§5、既定タップ宣誓・抜き打ち時のみ写真）
→ 稼働前 車両点検撮影（§6、SVGガイド、人単位スキップ可）
→ オドメーターOCR（§7、+画像、承認→自動記録）
→ 天気予報（§9）＋「お気をつけていってらっしゃい」
```
※ 私用は事前申請/常時許可、整備・移動は別入口（§4）。稼働でアサインが無くても「稼働」記録可（shift_id任意、シフト外稼働は運営に可視化）。

## 3. チェックアウト（返却）フロー

返却時に **稼働後点検 → オドメーター → 駐車位置 → 運営通知** を束ねる。送信忘れは**ソフトの強制力**で防ぐ:
0. **★QRは最後（順序が肝）**: 終了メーターOCR・駐車位置・日報など**諸入力を全て済ませた後に、最後に車両QRをスキャンして業務終了を確定**する。スキャン時刻=退勤時刻、スキャン時GPS=駐車位置。これにより「下車後に車から離れてから適当にメーター入力／駐車位置がズレる」を構造的に防ぐ（出勤=QR先頭・退勤=QR末尾の非対称）。QR不可時はナンバープレートOCR(§8.5)で確定（`end_method='plate_ocr'`）。
1. **必須ゲート**: 返却完了までセッションがopen（当日勤務を完了にできない）。完了は車両QRスキャンで確定。
2. **リマインド→エスカレーション**: 時刻まで未返却ならドライバーへpush、なお未了なら運営へ通知。
3. **運営ダッシュボードに「未返却（openセッション）」一覧**。
4. **日報提出に統合**して飛ばせなくする。

## 4. 利用目的：稼働が主役・私用は事前申請・整備は別入口

**システムはゲートでなく記録者**（シフトで車両利用を縛らない）。ただし「シフトの人に毎回目的を聞く」UXは避け、稼働を既定に、例外を別動線へ。

| 目的 | 入口 | 扱い |
|---|---|---|
| **稼働 (work)** | 稼働開始ページ（既定・ピッカーなし） | 当日アサインがあれば紐付け、無くても稼働可（shift_id任意） |
| **移動/整備 (move)** | **別入口「車両整備・移動」**（QRスキャン起点） | 移動(回送)/給油/オイル交換 等。**給油=メーター＋金額＋給油量＋レシート写真**（経費/燃費算出に接続）、オイル交換=既存オイル管理に接続 |
| **私用 (private)** | **事前申請** or **常時許可** | ①事前申請→運営承認、②membershipに「常時私用OK」設定。利用時にprivate記録。保険・責任 |

- どの利用でも**オドメーターは記録**（走行距離の連続性）。**点検の軽重は目的（稼働/移動/整備/私用）ごとに org 設定で可変**（§12）。
- 鍵BOX導入時はこの動線が複雑化 → **別途・先送り**（だいぶ先）。
- 標準permission: `membership.private_use_allowed`（常時許可）＋ 事前申請レコード（任意期間・運営承認）。

## 5. 免許携帯確認（要相談 → 軽く・設定可能・短期保持）

- 意図: 乗車状態での**携帯確認**（免許の主用途＝毎日の携帯確認、OCRなし）。順番は乗車直後で妥当。
- **毎日フル写真は避ける**（免許画像は最センシティブPII。毎日全員分ためると過大）。
- **既定＝タップ宣誓**「携帯しています」。**抜き打ち写真はorg単位設定**（有効な会社のみ、ランダム日に写真要求）。毎日フル写真はしない。
- **抜き打ち写真は長期保有しない（確定）**。**保持期間=7日の時間ベース自動削除**（最センシティブPIIをリスク最小で扱う）。オンボーディングのKYC免許画像（正本）とは別物。
- **有効期限ガード**: 登録免許の期限が近い/切れていれば警告/ブロック（オンボーディングデータ活用）。← 携帯確認より価値が高い。

## 6. 車両点検（状態写真）

- 目的: 傷・こすり検出と責任所在。タイミング: 稼働前＋稼働後（新規損傷検出）。
- **撮影セット＋SVGガイド**: 標準セット（前後左右/角4/8点）を用意、各角度にSVGガイド絵を重ねて誘導。どのセットかは org選択。
- **要否・撮影セットは「ドライバー単位」＋「車両単位」の両軸で設定可**（確定2026-06-25。旧案の「車両単位の上書きなし」を変更）。
  - **優先ルール = より厳しい方が勝つ**（必須 > 任意 > スキップ／撮影セットは点数の多い方）。例: 高額車を「車両=必須」にすれば、ドライバーが「人=スキップ」でも撮影必須。逆も同様。
  - 既定はドライバー単位（人ごとトグルで簡潔）。車両単位は高額車/特定車の上書き用。**実効設定はサーバで `max(driver, vehicle)` の厳しさを算出**。
- 損傷判定は当面 運営の目視（稼働前/後を比較）。AIは将来。

## 7. オドメーター OCR（端末側で完結）

- 端末側（ML Kit等）: 数字のみ・無料・オフライン・PIIなし（免許証OCRと違い今やれる）。
- **写真も必ず保存**（写真が真実、誤読は手修正）。
- **写真は運営承認まで必須保持**（確定）: 承認の証跡なので**承認前は削除しない**。承認後に保存期間ティア(3/6/12ヶ月 §11)へ乗せて自動削除。点検写真の一律ティアとは保持要件が異なる。
- **承認→自動記録は現状踏襲**: 既存パイプラインで車両走行距離更新 → オイル交換アラート＋日報メーターに流用。接続先は実装時に現行コードで確認。
- **ドライバー別 走行距離の累計（派生指標・新規）**: `vehicle_sessions` の `(end_odometer − start_odometer)` を `recorded_by`(=ドライバー) で集計して算出。**専用テーブルは持たず派生**（集計ビュー or 集計時計算）。ガード: 差分が負/巻き戻し/異常値/欠損はスキップ＋フラグ。用途=運営の勤怠/集計・ドライバー本人のマイページ表示。

## 8. 車両QR（ローテーション式トークン＋退避ルート）

QRは業務開始・返却・会社間貸与の引き取り・各種報告の**共通起点**（意味はアプリが文脈判断）。ただし**静的ID直書きは廃止**し、再発行で失効できるトークン式に変更する（偽造・重複入力・紛失ラベルの不正使用を防ぐ）。

### 8.1 トークンモデル（静的 `vehicles.id` 直書きを廃止）
- QRには車両IDを直接埋めず、**不透明トークン**（推測不可なランダム文字列）を埋める。サーバが token→vehicle を解決。
- **1車両につき有効トークンは常に1つ**。再発行で `version+1`、旧トークンは即 `revoked`。
- QRペイロード: `nippo://v/<token>`（将来のディープリンク/URL誘導にも流用可）。
- **トークン解決はグローバル（テナント横断）**: `token→vehicle` は org 非依存で解決（車両IDはグローバル一意 / platform-design §5）。スキャンした人の権限判定は**別レイヤ**＝**所有org**（`vehicles.owner_org_id`）**or 有効な貸与（`vehicle_loans`）を持つ借用org** なら許可。どちらでもなければ `not_authorized`（§8.3）。これにより**会社を跨いだ貸し借り中でも、借用orgのドライバーがそのままQRで打刻**できる（セッションの `org_id` は使用org＝借用org、§1/§13）。
- **発行/再発行/失効/有効化は所有orgの権限**（借用orgは使うだけで再印刷はしない）。所有orgがQRを再発行すれば、貸与中でも旧ラベルは失効する。

```sql
CREATE TABLE vehicle_qr (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  vehicle_id uuid NOT NULL REFERENCES vehicles(id),
  org_id uuid NOT NULL,                  -- 発行org（所有org）
  token text NOT NULL UNIQUE,            -- 不透明・推測不可（QRに埋める値）
  version integer NOT NULL DEFAULT 1,
  status text NOT NULL DEFAULT 'issued', -- 'issued' | 'active' | 'revoked'
  issued_at timestamptz NOT NULL DEFAULT now(),
  issued_by uuid,                        -- membership（発行者）
  attached_confirmed_at timestamptz,     -- 貼付確認(有効化)時刻
  attached_confirmed_by uuid,            -- ADMIN等（有効化した人）
  revoked_at timestamptz
);
-- 有効(issued/active)トークンは車両に1つだけ。revokedは履歴として残す
CREATE UNIQUE INDEX ON vehicle_qr (vehicle_id) WHERE status <> 'revoked';
CREATE INDEX ON vehicle_qr (token);
```

### 8.2 ライフサイクル（発行→印刷→貼付→★有効化→失効）
```
[発行]   org画面で「QR発行/再発行」→ token生成(status=issued, version+1)
         └ 再発行時は ★警告(8.4) → 確認 → 旧token 即 revoked
[印刷]   QR＋車番＋会社名のベクターPDF/画像をDL → 物理ラベル
[貼付]   車両へ貼る
[有効化] ADMIN等がアプリで該当QRをスキャン →「車両Xを有効化」確認
         └ status=active, attached_confirmed_at/by 記録（=実機で読める＋正しい車両を確認）
[運用]   active のみドライバー出勤可。issued(未有効化)スキャンは「貼付確認待ち」エラー
[失効]   再発行 or 手動失効で revoked。以後スキャン拒否
```
- **貼付確認(有効化)が肝**: 印刷ミス・誤った車両への貼付を、ADMINの実機スキャンで弾く。トークンのローテーションと自然に噛み合う。
- **QRラベルはorg画面からいつでもDL**（紛失/破損で再印刷）。ただし再印刷=再発行=旧失効なので 8.4 の警告を必ず出す。
- 場所QR/鍵ボックスは物理強制・屋内精度が欲しい会社の任意アドオン（標準外）。

### 8.3 スキャンエラーの可視化（無言失敗を作らない）
スキャン結果は必ず**理由付き**で提示し、「何で打刻できないのか」を本人がその場で理解できるようにする。

| 判定 | 原因 | ドライバー画面 | 運営/ログ |
|---|---|---|---|
| ok | active＋org一致 | 続行 | event記録 |
| revoked | 再発行で失効した旧ラベル | 「このQRは新しいものに貼り替えられています。新ラベルを使うか運営へ連絡」 | 失効ラベル使用を記録 |
| pending_attach | issued（未有効化） | 「このQRはまだ有効化されていません（貼付確認待ち）」→ 退避ルート(8.5)案内 | 有効化を促す |
| not_authorized | 所有orgでも有効な貸与中の借用orgでもない | 「この車両は利用できません（貸与の登録が必要かもしれません）」 | 未認可スキャンを記録。運営に貸与(`vehicle_loans`)登録を促す |
| unknown | 不明/破損/偽造トークン | 「読み取れませんでした。ナンバープレートで打刻できます（8.5）」 | 不正トークンを記録 |
| vehicle_inactive | 廃車/無効化車両 | 「この車両は現在使えません」 | — |

### 8.4 再発行の警告（失効を明示）
org画面で再発行/再印刷を押すと確認ダイアログを必ず表示：
> ⚠ 再発行すると**現在のQRは即座に失効**します。貼付済みラベルは読めなくなり、**新ラベルの印刷→貼付→ADMIN有効化**が必要です。続行しますか？
- 失効から新有効化までの間、その車両は**QR出勤不可** → 8.5 の退避ルートが効く。
- 運営一覧に「**QR未有効化／失効中の車両**」を表示し、貼り替え漏れを可視化。

### 8.5 退避ルート：ナンバープレートOCR打刻
QRが破損/未有効化/読めない時の代替。**QRが原則・プレートは例外**。
- フロー: 「QRが読めない」→「ナンバープレートで打刻」→ プレートをカメラOCR（端末側）→ `vehicles.plate_number`（org内）で照合 → 候補提示 → ドライバーが車両を確認 → 続行。
- 照合が曖昧（複数候補/不一致）なら一覧から手選択。**プレート写真を証跡として保存**。
- **信頼度を下げて記録**: セッションの `start_method`/`end_method` = `'plate_ocr'`（QRは `'qr'`）。運営一覧で「**QR未使用（要確認）**」として可視化。常用される車両はQRが死んでいる兆候 → 再発行を促す。
- それも無理な場合の最終手段 `'manual'`（手動車両選択）は**運営承認制**: ドライバーは打刻を**申請**（車両を手選択＋理由＋任意で写真）→ セッションは仮確定（`method='manual'`, 承認待ちフラグ）→ **運営が承認して確定**。不正打刻を抑止。承認前は運営一覧に「manual打刻 承認待ち」で表示。

## 9. 位置・運営マップ・天気

- **チェックイン/チェックアウト時に位置を記録**（単発イベント＝Realtime不要）。
- **GPSは任意・フローを止めない**: 許可拒否/取得失敗でも打刻は必ず成立。打刻のたびONを促し（未許可ならバナー＋許可ダイアログ、許可済みはサイレント取得）、各打刻に状態を保存：`gps_status = 'captured' | 'denied'(権限OFF) | 'unavailable'(取得失敗)`（`vehicle_sessions.start_gps_status`/`end_gps_status`、§1）。
- **運営側で可視化**: 「GPS無し」「権限OFF」を一覧で色/アイコン表示し、常時OFFのドライバーを運営が把握できる。
- **運営マップ**: openセッション（乗り込み中＝今出ている車）と最新駐車位置をピン表示。イベント時/ポーリングで更新（ライブ追跡ではない）。各ピンに鮮度・記録者・目的。
- **天気**: 気象庁データ（無料）or OpenWeather。チェックイン位置で当日予報を表示。優先度低・実装軽い。

```sql
CREATE TABLE vehicle_inspections (

```

## 11. Storage 戦略（点検写真が最大の増加要因）

- 試算: 圧縮後1枚~300KB、1稼働3〜5MB/人 → 月3〜6GB/社(50人)。超過単価は安い(~$0.021/GB/月)が削除しないと無限増。
- **保存期間を各社設定にして料金ティア化(3/6/12ヶ月)＋期限超過自動削除** → 定常化。コスト制御＋課金レバー。
- **端末側で圧縮してアップロード**。点検・携帯確認写真は「書いて滅多に読まない」→ 高コスト化したらR2等へ退避（egress無料・~$0.015/GB）。まずSupabase＋圧縮＋保存期間でstart。
- **例外: オドメーター写真は「運営承認まで保持」が優先**（§7）。ティア削除は承認後にのみ適用。免許の抜き打ち写真は7日固定（§5）。

## 12. org設定（各要素は独立）

点検写真／オドメーター／駐車位置／免許携帯確認 を**各々独立に 必須/任意/スキップ**。撮影セット、スキップの**ドライバー単位＋車両単位（両軸・厳しい方優先 §6）**、リマインド時刻、保存期間ティア、免許確認の厳格さも org 設定。
- **点検の重さは目的ごとに可変**（確定）: 稼働/移動/整備/私用 それぞれに点検の要否を org が設定（例: 稼働=前後フル、移動=メーターのみ、私用=メーター＋簡易）。既定は安全側（稼働フル・他は軽量）。

---

## 13. テナント／貸借（★車両だけはマルチテナント横断）

基盤は platform-design §5「車両のグローバル一意化と会社間貸借」（`vehicles.owner_org_id` ＋ `vehicle_loans`）。**車両アイデンティティだけはグローバル一意**で、人・案件・日報などの他データは org スコープに閉じる。

- **QRはグローバル解決・権限は貸借対応**（§8.1）: 借用orgのドライバーが所有orgのQRをそのままスキャンして打刻できる。`token→vehicle` はorg非依存、認可は所有org or 有効貸与の借用org。
- `org_id` は使用org（貸与中は借用org）。点検・オドメーター・セッション・駐車位置も借用org文脈で記録。
- **所有org（owner_org_id）には走行距離・点検・最新位置をフル開示**（自社資産の状態管理）。**借用側ドライバーの個人情報はスコープ外**（見せるのは車両であって人ではない）。
- **借用org→所有orgの逆方向開示は限定**（運行に必要なメーター/ナンバーのみ。所有者のリース代・財務は不可。platform-design §5）。
- **貸与の引き取り/返却**も同じ車両QRスキャンが起点（platform-design §5 の `vehicle_loans` と接続。スキャンで「この車両を今 from 借りる」を確定）。
- **発行/失効は所有orgのみ**（§8）。貸与期間の終了で借用orgの認可は自動的に外れる（`vehicle_loans` の期間外 → `not_authorized`）。

## 14. エッジケース

| ケース | 挙動（案） |
|---|---|
| OCR誤読 | 写真を正として手修正 |
| 点検スキップ設定中（その人） | 写真省略、他要素は要否に従う |
| 私用で認可未取得 | 利用記録は作るが「認可待ち」フラグ＋運営通知 |
| 稼働後点検で新規傷 | 両phase保持で比較。損傷フラグ＋運営通知（将来） |
| 未返却（openのまま） | エスカレーション（§3） |
| 貸与車両 | org_id=借用org。所有orgは距離・点検・位置を閲覧（人は除く） |
| GPS拒否/屋内 | 写真＋メモで補完、accuracy保存。`gps_status` に denied/unavailable 記録（§9） |
| QR失効（再発行後の旧ラベル） | revokedエラーで理由提示（§8.3）。新ラベルへ誘導。運営に失効ラベル使用を記録 |
| QR未有効化（貼付確認前） | pending_attachエラー。ナンバープレートOCR(§8.5)で打刻継続可、運営にQR有効化を促す |
| QR破損/読めない | ナンバープレートOCR(§8.5)へ退避。`method='plate_ocr'`で「要確認」可視化 |
| プレートOCR誤読/多重一致 | 候補一覧から手選択＋プレート写真保存。最終手段は manual（運営フラグ強） |
