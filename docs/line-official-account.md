# LINE 公式アカウントの画面づくり（運用手順）

最終更新: 2026-08-15 ／ 設計の正本: `docs/notification-flow.md`

ここは**コードではなく LINE Official Account Manager 側の設定**をまとめた手順書。
アプリ側の実装は「遷移先 URL を用意すること」までで、メニューの配置・画像・文言は
LINE の管理画面で行う（roadmap-2026-07 トラック E の残タスク①）。

対象アカウント: ハコ虎（統合公式アカウント1本。notification-flow §1-1）。

---

## 0. 前提となる環境変数

| 変数 | 用途 | 未設定時 |
|---|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | push / multicast / reply | LINE 配信を丸ごとスキップ（インボックスのみ） |
| `LINE_CHANNEL_SECRET` | webhook の署名検証 | 同上。webhook は全て拒否 |
| `NEXT_PUBLIC_LINE_ADD_FRIEND_URL` | マイページの「友だち追加」ボタン | ボタンを出さない |
| `APP_BASE_URL` | **通知・リッチメニューから開くアプリの URL** | Vercel の本番ドメインを使う。それも無ければリンクを出さない |

`APP_BASE_URL` は独自ドメイン運用に切り替えたときだけ明示設定すればよい
（未設定なら `VERCEL_PROJECT_PRODUCTION_URL` から本番ドメインを組み立てる。`apps/web/src/server/appUrl.ts`）。

**プレビュー環境の URL を入れないこと。** ドライバーの端末で開かれるリンクなので、
必ず本番を指す必要がある。

## 1. リッチメニュー

「アプリの操作面」として全社共通（notification-flow §1-1）。org 別の出し分けはしない。

### 構成（6分割・上下2段×3列）

| 位置 | ラベル | 種別 | 遷移先 |
|---|---|---|---|
| 左上 | シフト確認 | リンク | `{APP_BASE_URL}/shifts` |
| 中央上 | 日報を出す | リンク | `{APP_BASE_URL}/report` |
| 右上 | お知らせ | リンク | `{APP_BASE_URL}/notifications` |
| 左下 | マイページ | リンク | `{APP_BASE_URL}/me` |
| 中央下 | 希望休の提出 | リンク | `{APP_BASE_URL}/submit` |
| 右下 | 運営に連絡 | テキスト送信 | （何も設定せずトークを開く）※下記参照 |

- 「運営に連絡」はリンクではなく**トークを開くだけ**にする。連携済みの人がここに書いた内容は
  webhook が `line_chat_messages` に保存し、運営画面の「通知配信 > チャット」に届く
  （自動応答はしない）。
- **リンク先はいずれもログインが要る。** 未ログインなら `/login` に飛ぶだけで壊れない。
- 表示期間は「期間なし（デフォルト表示）」。切り替え運用はしない。

### 画像

- サイズ: 2500×1686px（大）を推奨。分割テンプレートは LINE の管理画面のものを使う。
- **絵文字は使わない**（ワークスペース規約）。アイコンはブランドガイドラインに合わせて作成する
  （`docs/hakotora-brand-guidelines.md`）。

## 2. あいさつメッセージ（友だち追加時）

webhook 側で `follow` イベントに応答している（`apps/web/src/app/api/line/webhook/route.ts`）ため、
**LINE 管理画面のあいさつメッセージは OFF にする**（二重に届くのを防ぐ）。

webhook が返す文面:

- 連携済みの人が再フォローした場合 —
  「友だち追加ありがとうございます。引き続きこちらにお知らせをお送りします。」
- まだ連携していない人 —
  「友だち追加ありがとうございます。」＋
  「アプリの「LINE連携」画面に表示される6桁の連携コードを、このトークにそのまま送信してください。」

## 3. 応答設定

| 項目 | 設定 |
|---|---|
| 応答モード | **チャット**（Bot ではなくチャット側にしないと webhook とチャットが両立しない） |
| あいさつメッセージ | **OFF**（webhook が返すため） |
| 自動応答メッセージ | **OFF** |
| Webhook | **ON** |
| Webhook URL | `{APP_BASE_URL}/api/line/webhook` |

`LINE_CHANNEL_SECRET` が未設定だと署名検証が常に失敗して全イベントを拒否する（default-deny）。
Webhook を ON にする前に環境変数を確認すること。

## 4. 通知の見え方（実装済み・参考）

予定の通知は Flex Message のカードで届く（`apps/web/src/server/line/flex.ts`）。

- 見出しの色で種別が分かる: 通常=濃紺 / 変更=オレンジ / 取消=赤 / 休み=グレー
- 明細（コース・集合時刻・集合場所・車両）は org 設定のトグルで出し分け
- 変更のときは変わった項目の下に**変更前の値を取り消し線**で添える
- ボタン: 「カレンダーに追加」（Google カレンダーの予定作成画面が開く）／「アプリでシフトを見る」

**通数課金はメッセージ1通単位**なので、カード化してもテキスト時代とコストは変わらない。
LINE の通知バナーとトーク一覧に出るのは `altText`（＝テキスト版と同じ文面）。

## 5. 認証済みアカウント（青バッジ）の申請

法人登記後の事務手続きで、実装とは独立。申請時に必要になるもの:

- 法人の登記情報
- 事業内容が分かる Web サイト
- アカウントの用途説明（自社ドライバーへの業務連絡）

未認証のままでも push / multicast / webhook は動く。バッジは信頼性の表示と、
友だち追加の検索性のためのもの。

## 6. まだ手を付けていないこと

- **通知テンプレートの org 別 CMS**（`org_message_templates`）。
  現状の文面は `packages/core/src/logic/notificationMessage.ts` で組み立てており、
  org 側で変えられるのは「項目を含めるか」のトグルだけ。
  カード化で文面が構造化されたため、自由入力テンプレートよりも
  「項目の出し分け＋ひとこと添え書き」の形の方が実態に合う可能性がある（要検討）。
- リッチメニューの org 別出し分け（BYO-LINE を提供するまで不要）。
