### A. シフト業務の作り替え（web・最優先）
- [x] **A1: 配車とシフト編集の権限切り分け** ✅ 2026-07-20 — `can_dispatch` を新設し
      車両割当を `POST /api/admin/shifts/vehicle` に分離（vehicle-loans も can_dispatch 化）。
      シフト upsert から vehicle_id を除去（ドライバー解除時のみ連動クリア）。
      migration 105 で can_manage_shifts 保持ロールへ can_dispatch を付与（挙動維持）。
      UI はセル単位で出し分け: コース割当=can_manage_shifts / 車両・貸出=can_dispatch、
      配車のみの担当は割当済みセルだけ編集ポップオーバーを開ける。
- [x] **A2: コース／シフトの時間モデル** ✅ 2026-07-20 — 合意: 標準時間はコースごとに一定
      （曜日別パターンなし）→ courses に default 列 meeting_place / meeting_time / arrival_time /
      end_time、shifts に同名の上書き列（NULL=コース標準、実効値 = shifts.* ?? courses.*）。
      migration 106。コース設定モーダルに標準時間・集合場所の入力、シフトのセル編集モーダルに
      実効値の表示＋日別上書き（POST /api/admin/shifts/times、can_manage_shifts。
      「コース標準に戻す」で上書き解除）。セルのコースツールチップにも標準時間を併記。
      **残り: ドライバー画面（/api/me/shifts 系）への時間表示は未**（mobile 刷新時 or A3 で）。
      ※「便区分（旧: 時間帯、shift_request_slots）=分類」と「標準時間=実時刻」の2概念は当面併存
      （コース設定 UI では1つの「時間」セクションに集約しラベルで役割を明示済み）。
      **概念の本整理は将来課題** — C の AI 制約定義（休み希望と実時刻の突き合わせ）を作るときに再訪する。
- [ ] **A3: シフト画面のUI改善（洗い出し 2026-07-20 実施）** — Quick win 4件は同日対応済み:
      ①今日の列へ自動横スクロール ②未割当一覧の中央モーダル化（アンカー式ポップオーバー全廃）
      ③便指定休バッジ拡大（9→11px） ④~~セル編集モーダルの車両リストから貸出中トグル~~
      →**撤回**（車両選択＝その人に割り当てる車を選ぶ文脈に貸出設定は合わない、との判断）。
      代わりに貸出表（車両×日）を**押しながらなぞって一括設定**に対応（ON時に割当済みセルは
      スキップ＋まとめて通知）。貸出まわりのUIは今後改めて設計する。
      あわせて**叩き台生成（ルールベース）を廃止**（UI・API とも削除。シフト自動作成は C の
      AI 駆動・制約充足として再実装する方針）。
      入力効率系も同日対応済み: **D&Dコピー**（割当セルをドラッグ→同一ドライバー行は範囲フィル・
      別ドライバーは単セルコピー。希望休/担当外/定員満は自動スキップ＋まとめて通知。車両・時間上書きは
      コピーしない）＋**コース軸ビュー**（ヘッダーで軸切替。行=コース・セル=割当ドライバー、
      セルクリックでコース×日モーダル＝担当可能ドライバーの追加・解除）。
      ※空き枠バッジ（日付ヘッダー「空きN」）は一度入れたが**毎日走らないコースがあり定員基準の
      空きはノイズ**とのフィードバックで撤去（コース軸ビューのセル内に控えめ表示のみ残す）。
      表示系も同日対応済み: **表示密度3段切替**（簡易=コースのみ/標準=＋車両/詳細=＋実効集合時刻。
      localStorage 記憶）＋**手動リフレッシュボタン**（他管理者の変更を取り込む。自動再検証は
      楽観更新と衝突するため手動のみ）。A3 の洗い出し分はこれで全消化 — 以後は運用フィードバック起点。
- [ ] **A4: 場所マスタ・マップ連携** — A2 の meeting_place(自由テキスト)を org_places マスタへ昇格:
      name / kind(集合・駐車・倉庫…) / address / lat・lng / map_url。courses・shifts は ID 参照＋
      テキスト併存で段階移行。マップはまず共有リンク方式(APIキー不要、モバイルはネイティブマップが
      開いてナビ可)。駐車場所の登録・車両との紐づけもこのマスタに載せる。埋め込み地図/ジオコーディングは
      実需が出てから(Maps API 従量課金)。

### B. 管理画面のレスポンシブ（スマホ）対応
- [x] 外枠（ダークシェル・メニュー・FAB）は対応済み。
- [x] **シフト・日報・名簿 ✅ 2026-07-20**:
      シフト=A3 の改修（中央モーダル・横スクロール・今日へ自動スクロール）＋ツールバーのトグル1行シェア。
      日報=元からカード化/table-scroll 済み。統計カード3枚をスマホで縮小（gap/padding/数字サイズ）。
      名簿=**一覧をスマホでカード化**（md 未満。顔写真・コース・免許・権限セレクトまで1画面で完結、
      タップで編集モーダル）、ヘッダー行の折返し、編集モーダル内の2列グリッドをスマホ1列化。
      ※日報の編集/代理入力モーダルの2列グリッドは数値入力ペアのため据え置き（1列化は縦長化の害が大きい）。
- [x] **実機フィードバック対応 ✅ 2026-07-20**:
      ①モバイルドロワーを常時マウント＋translate-x 遷移でスライド開閉（従来は条件付きマウントで
      アニメーションが効いていなかった） ②モバイルヘッダー z-30→z-40（ページ内 sticky と重なる不具合）
      ③車両カードの「次回車検/自賠責更新」をペア単位で折返し（はみ出し解消）＋メーター見出しの折返し
      ④**シフトはスマホ専用の日別ビューを新設**（1日ずつ縦リスト＝横スクロール不要。前後日ナビ・稼働人数、
      **全員/稼働/未割当のタブ切替**で在籍者を一覧（各行に コース・車両プレート・希望休バッジ）。
      タップで既存の編集モーダル（希望休の行は希望休モーダル）。軸/密度切替とD&DはPC専用に）。
- [x] **車両・ロール・実機フィードバック2巡目 ✅ 2026-07-20**:
      車両カードの1行化（No./メーカー/車種/ドライバー/期限を小さめフォントで詰める）、
      ナンバープレートと車両画像をスマホで横並び、見出し＋オイル警告の追従。
      ロール画面はカード高さ揃え・**ドラッグ並べ替え**・メンバー割当の楽観更新（体感即時）。
      シフトのスマホは**日別ビュー**（タブ=全員/稼働/未割当、行に車両プレート、
      **ページめくり式スワイプ**でプレビューしながら前後日へ）。
      ※固定ヘッダーの貼り付き位置は AdminLayout がモバイルヘッダーの実高さを測って
      CSS 変数 `--admin-header-h` に公開する方式に統一（固定 px だと端末差でズレて潜り込む）。
      スマホで固定するのは日付ナビ＋タブのみ（ツールバー全体を固定すると一覧が隠れる）。
- [x] **収支系 ✅ 2026-07-20**（監査 → 高5件/中5件を対応）:
      請求書＝編集画面に**PC限定ゲート**を追加（新規作成にはあったが編集に無く、スマホのカードから
      A4 エディタに入れてしまう穴。判定と案内は `DesktopOnlyNotice` に共通化）／4フォルダペインは
      スマホで内部スクロール化（縦積み 1560px → 1画面弱）＋右ペインの 520px 固定は xl 限定に／
      フィルタ・アップロードバー・ヘッダーの折返し／帳票画面の `-m-6` をスマホで `-mx-3 -my-4` に
      （左右の溢れ解消）＋プレビューのツールバーを sticky 化。
      ペイメント＝**カード化**（8列テーブルの横スクロール解消。収入明細は PC の展開行と共通関数に切り出し）
      ＋モーダル内テーブルにスクロールラッパー。
      取引先＝**カード化**（外800px×内720pxの**二重横スクロール**もこれで解消）＋統合モーダルに
      `max-h`/スクロール制約。
      売上＝日別マトリクス（期間×ドライバーで 2000px 超）はスマホでは**ドライバー別の期間合計**に畳む
      （日別内訳は PC）。日次カードの固定 150px を縮小可に。
      ※グラフは `ResponsiveContainer`＋`clamp` 高さで既にレスポンシブ（対応不要だった）。
      ※請求書の帳票（InvoiceSheet）は A4 再現が目的なので**横スクロール前提のまま**とする（作り替え非推奨）。
- [ ] B の残り: 実機での確認と、細かい調整（運用フィードバック起点）。
