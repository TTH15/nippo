## Web共通の操作ルール（2026-08-30）

管理画面を含むWeb共通の規約。新規・改修する画面では以下の部品を再利用する。
並べ替え・開閉・選択の反応を画面ごとにハードコードしない。

| 操作 | 共通部品 | 表示・挙動 |
| --- | --- | --- |
| カードの詳細開閉 | `src/lib/components/SmoothCollapse.tsx` | 高さ0↔autoと透明度を250ms、ease `[0.22, 1, 0.36, 1]` で変化。初期描画では展開アニメーションをしない |
| 縦リストの並べ替え | `src/lib/components/SortableList.tsx` | Font Awesomeの`faGripVertical`をハンドルに使う。カード全体がポインタに追従し、他のカードはspringで移動する |
| チェック項目 | `src/lib/components/CheckboxField.tsx` | 標準inputの操作を維持。チャコールの面＋アンバーのチェック印、選択行は淡いアンバー。ラベル全体を押せる |
| ラジオ・選択肢の回答 | `RadioField.tsx` / `ChoiceInput.tsx` | 単一選択は標準radio、複数選択はCheckboxField。同じ44px操作領域とチャコール＋アンバーの配色 |
| 選択・日付 | `CustomSelect.tsx` / `DatePicker.tsx` | 既存の共通部品を使用。OS依存の見た目に戻さない |
| 車両選択 | `VehiclePlate.tsx` / `VehiclePlatePicker.tsx` | 番号のテキストだけでなくプレートから選ぶ。選択中も同じ描画を使う。候補は番号・車種で検索でき、選択を背景・枠で示す。チェック用の余白を設けない |
| フォームの入力形式 | `FieldTypeSelect.tsx` | Font Awesomeの形式別アイコン、短い名称、用途の説明を併用。既存CustomSelectを再利用 |

### フォームをその場で編集するUI

- フォームビルダーは一列のカード上で項目名・入力欄・選択肢を編集する。編集用ラベルと独立した入力プレビューを左右に重複表示しない。記録の入力画面でも同じ入力部品と並び順を使う。
- 項目名は見出し位置のinputで直接編集する。余白や入力欄へのクリック、項目名へのフォーカスでカードを選択し、必須・複製・削除・入力の詳細設定をSmoothCollapseで開く。文字編集とドラッグハンドルを分離する。
- 選択肢はカード内の表示位置で直接編集する。設定と試し入力を区別し、試し入力の値はフォーム定義に保存しない。
- 形式は `FieldTypeSelect` を使用。アイコンだけに頼らず、名称と用途説明も表示する。名称と推定規則は `src/lib/formBuilder/fieldTypes.ts` に集約する。
- 項目名からの自動選択は新規項目で開始する。既存項目・テンプレート・複製項目・手動で形式を選んだ項目は自動変更しない。利用者が明示的にONにした場合だけ再開する。
- 自動選択は入力が450ms落ち着いてから行い、IME変換中には実行しない。自動変更した形式は表示し、「元に戻す」で直前の形式へ戻して自動選択をOFFにする。
- 現時点では確度の高い日本語の項目名をローカルの規則で判定する。氏名と組織メンバー、番号と数値、日数と日付を区別する。不明なら短い文章を使用し、手動選択を可能にする。AIや外部サービスへ項目名を送信しない。
- 型変更で既存記録を変換しない。定義内の選択肢や数値設定は、形式を行き来しても保持し、現在の形式に関係する設定だけを入力・検証に使う。

### 選択肢の「その他」

- 「その他（自由入力）」は通常の選択肢と分ける。フォーム定義の`allowOther`で明示的に有効化し、ビルダーでは「その他」を追加・削除する専用操作を置く。ラベルやIDが`other`というだけで既存の選択肢を自動変換しない。
- 共通`ChoiceInput`を使い、選ぶとSmoothCollapseで自由入力欄を開く。項目全体が任意でも「その他」を選択した場合は内容を必須にする（空白のみ不可・最大500文字）。標準radioのキー操作を妨げないよう、選択時に入力欄へフォーカスを強制移動しない。
- 単一選択は通常項目と「その他」を排他的に扱う。複数選択は併用可。「その他」を外した場合は自由入力を回答から除き、複数選択の通常項目は保持する。
- 自由入力は`{ selected: string[], other: string }`として選択肢IDと分離する。単一選択の`selected`は空配列。通常回答の文字列/配列と互換性を維持し、未知のID・重複・不正な型・単一選択での同時指定は検証で拒否する。
- 表示・検索には「その他：入力内容」を使う。既存記録は保存時の定義を保持し、新しい定義から「その他」を削除しても過去の自由入力を失わない。
- ビルダー内の試し選択では編集モードへ強制切替しない。見出しの直接編集、または「選択肢を編集」から定義編集へ移る。

### 並べ替え

- ハンドルは左側に置き、操作領域は最低44×44px。上下矢印ボタンは基本形にしない。
- ハンドルだけをドラッグ可能にする。カード見出しは開閉または直接編集に使い、ドラッグと干渉させない。ハンドルのみ`touch-action: none`とし、それ以外ではタッチスクロールを妨げない。
- つかんだカードは1.012倍の控えめな拡大・浮いた影・アンバーの輪郭で表す。周囲のカードと着地には `src/lib/ui/motion.ts` のspring（stiffness 420 / damping 32 / mass 0.8）を使う。本文を引き伸ばさないよう、レイアウト補間はpositionに限定する。
- ハンドルにフォーカスしてSpace/Enterで開始、上下キー（Home/Endも可）で移動、Space/Enterで確定、Escapeで取り消す。Tab・フォーカス離脱でも確定する。移動中の位置をlive regionで読み上げる。ポインタのドラッグもEscapeで取り消せる。
- 安定した項目IDをkeyと値に使う。並べ替えても入力中の値・開閉状態・フォーカスを項目に保持し、取り消しでは順序だけを復元する。1項目だけならハンドルは無効。
- 共通部品は画面内の配列を更新するだけ。API保存のタイミング、認可、初期状態など業務上の順序の意味は呼び出し側で管理する。複数列・別リストへの移動や仮想化一覧はこの部品の対象外。

### 開閉・選択とアクセシビリティ

- 開閉専用の見出しはbuttonで実装し、`aria-expanded` / `aria-controls`を対応するパネルへ紐付ける。直接編集する見出しはinputとし、設定開閉とドラッグを別操作にする。シェブロンは開閉状態に使い、並べ替えハンドルと区別する。
- 閉じるアニメーション中の入力・ボタンはinertにして、見えなくなった内容にフォーカスが残る操作を防ぐ。フォームの値は呼び出し側で保持する。
- チェック項目も操作領域は高さ44px以上。ホバー・選択・押下を150msで反映し、押下中はチェック面だけを0.9倍にする。
- フォーカスはアンバーのリングで明示する。色だけで状態を伝えず、チェック印、形、`aria-*`を併用する。
- `prefers-reduced-motion`では開閉・並べ替えの補間、チェック面の縮小、シェブロンの回転アニメーションを停止する。ドラッグそのものの追従は操作に必要なため維持する。
- アニメーションは入力や保存を待たせる演出にしない。確認や権限変更のロジックは共通部品に持ち込まない。
- 確認モーダルは共通の `ConfirmDialog` を使い、確定ボタンに「破棄する」「削除する」「返却済みにする」など具体的な操作名を指定する。「実行する」「OK」で済ませない。キャンセルでは操作を適用せず、入力を維持する。文言の変更に保存・認可・業務上の順序の変更を混ぜない。

### 適用範囲と移行

- 日常業務と管理者向けの設定は入口・一覧を分ける。入力・閲覧画面にフォーム設計や新しい種類の作成ボタンを混在させない。左メニューの選択状態、対象名を含むページ名、親を明記した戻る操作で現在位置を示す。
- 作成・編集からは所属する一覧へ戻す。別の入口へ移る場合も未保存の内容を保護し、確認の取消で入力を維持する。設定対象を変えても日常業務側の選択中の種類は変えない。
- 一覧表示の設定は「必須」などの入力条件と分け、「記録の一覧に表示する項目」のように表示先を明記する。利用者向けのラベルに「カード」など見た目の実装用語を使わない。選択に連動した表示例を実際の一覧と同じ描画部品で示す（記録・報告では`RecordListCard`）。件名など常に表示するものに、効かない表示チェックを設けない。
- 一覧に載せない回答も詳細には残る。表示項目の設定と「公開・権限」を混同させず、非表示を認可・機密保護の代わりにしない。
- 記録・報告の対応状況は共通の「未対応・対応中・解決済み」とし、解決済みが対応終了。フォームごとの設定は利用のオン・オフだけにし、状態名や「完了として扱う」の設定を重ねない。オフでも過去の記録は消さず、解決済みでも編集権限を変更しない。

- 今回の適用先：記録・報告のフォーム項目並べ替え/詳細開閉/代理報告欄、既存のロール設定の詳細開閉。前回のチェック項目共通化も本規約に含める。
- 既存画面を一括置換せず、同じ操作を改修するときに移行する。ロールの順位など業務に影響する並べ替えは、保存・認可の検証を伴う別の移行として扱う。
- 基盤は既存依存のMotionを利用（[Reorder](https://motion.dev/docs/react-reorder)、[useDragControls](https://motion.dev/docs/react-use-drag-controls)）。新たなアニメーションライブラリは追加しない。
