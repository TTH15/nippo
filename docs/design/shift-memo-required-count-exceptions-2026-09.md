# シフトメモ：その日だけ必要人数を変える

2026/09/14、現行画面を調査して提案した「セルの人数から1日だけ変更する」案をユーザーが承認。同日、UI・保存・集計・隔離プレビューへ実装し、ユーザーの追加承認により23:23に本番公開した。公開記録は [日別必要人数の本番公開](../deployment/shift-memo-daily-count-2026-09-14.md)。

## 操作と表示

- 対象は担当枠×1日。セル右上の「あと1」「2/2」から人数変更を開く。
- 2026/09/15のユーザー指定で、見出しを大きな日付・コース名へ変更。「この日だけの必要人数」「この日に反映」は撤去。0〜10人の＋／−で即時更新・自動保存し、「通常:○人」とリセットボタンを表示する。閉じる／Escapeでも更新値は残る（このUI変更は本番未公開）。
- 例外を設定したセルにだけ「必要3人」を出す。不足の色付き表示とは区別し、画像・PDFにも人数を残す。
- スマホでは「この日の配置」の必要人数から同じ編集パネルを開ける。カードの人数ボタンと編集パネルの操作は高さ44px。
- 既存の休み／稼働の直接操作は維持。表の通常幅76pxでは人数表示と重ねず、72px未満へ列幅を狭めた場合は休み操作を次の段へ送る。表の数字は密度を優先した小さな入口なので、スマホには配置カードの入口も用意する。
- 通常人数の変更は従来の担当枠設定から行う。新しい設定タブ、常設の増減ボタン、複数日の一括変更、曜日ごとの繰返し設定は追加しない。

## 保存と集計

`PersonalShiftMemoBoard.tsx` の `StoredBoard` に任意の `requiredCountOverrides: Record<cellKey, number>` を追加した。`cellKey` は既存の配置と同じ担当枠ID＋ISO日付。休み／稼働の `dayOverrides` とは独立して保存する。

- 絶対数を保存する。通常2人から4人に変えても「この日は3人」は3人のまま。
- 通常と同じ人数に変更、またはリセットでその日の人数指定だけを削除する。他の日・配置・休み指定は変えない。
- 0人も有効。稼働／休みは変えず、配置済みより人数を減らしても名前札を削除・移動しない。不足は0未満にならない。
- 休みの不足は0。人数指定は保持し、再稼働したらその人数で集計する。
- `lib/shiftMemo/board.ts` の `resolveDayStaffing` をセル、日付別の不足合計、不足一覧、日別配置、出力へ適用した。
- 旧保存データは人数指定なしとして読む。不正な型・小数・範囲外の値は除外する。別の月、非表示の担当枠の指定は残す。
- 従来どおり端末・利用者ごとの個人メモに自動保存する。保存失敗では画面の内容を維持し、「保存を再試行」できる。
- 正式シフトの定員、自動作成、共有メモAPI、他端末同期には反映しない。DB変更はない。

## プレビューと確認結果

起動：`npm run preview:admin -- shifts --port 3193`

`http://127.0.0.1:3193/preview/shifts` → 「日別の必要人数を試す」→「シフトメモ」。本番 `shifts/page.tsx` と `PersonalShiftMemoBoard.tsx` をそのまま再利用。`scripts/previews/shifts-services.tsx` の架空データとプレビュー専用の保存キーを使い、本番認証・DB・API・通知から隔離した。

- 豊中1エリア：9/1は3人、9/2は1人、9/3は臨時休、9/6は非稼働＋人数指定3人、9/16は4人。通常は2人。従来の12枠／40枠サンプルは日別人数のない旧形式も確認できる。
- サンプル差替えは保存後にページを再読込する。担当枠のキー差替えで旧画面が重複して残るプレビューの問題も解消した。
- アプリ内ブラウザ：PC1280px、スマホ390px／320pxで人数パネルの収まり、カードからの44px操作、ページの横はみ出しなしを確認。
- 3人→4人で日付の不足合計10→11、通常2人へ戻すと9。セルの人数・名前札・例外の補足を確認。通常設定変更との独立性、前半／後半切替、再読込後の保持も確認した。
- キーボード：Shift+Tabのパネル内循環、Escapeで取消、入口へのフォーカス復帰を実操作で確認。選択中の名前札を人数ボタンのSpaceで配置してしまわないことはコンポーネントテストで確認。
- 全130ファイル・1,204テストと本番ビルド成功。日別人数の関連17テストには旧保存、0人、増減、通常復帰、休みとの独立、名前札保持、保存失敗と再試行を含む。
- PNG（2660×3238px）とPDF（1ページ・679,495バイト）を実際に保存し、PDFを画像へ変換して目視確認。日別人数・不足数・名前札が一致し、入力操作や選択枠は出ない。共通 `pngToPdf` を継続利用。
- 未検証：スマホ実機のタッチ、最小列幅56pxでの実ドラッグ、ブラウザ実環境の容量不足。後者は保存例外の自動テストで検証した。共有同期は対象外。本番公開後の業務データを使った編集テストは行っていない。
