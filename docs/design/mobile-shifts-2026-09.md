# モバイルのシフト確認（2026/09/24）

## 採用した表示

- 月カレンダー＋日別一覧。カレンダーは日付・便ごとの色マーカー・休みの背景色で概観し、小さい枠へコース名とプレートを詰め込まない。
- 日別一覧はコース正式名を省略せず折り返す。複数便は各便を並べ、集合/退勤予定、共通SVG字形由来のVehicleIdentityを表示する。
- 日付/日別カードのタップで詳細。正式コース名・便・集合/退勤予定・集合場所・使用車両のプレート/メーカー/車種を表示。時刻未設定・車両未割当・持込・車両読込失敗・利用停止を区別する。
- 希望休は既存shift_requestsの提出内容。便指定を全休に変換しない。全休希望と割当が重なる場合は確認を案内する。
- **ユーザー回答による指定休の定義: 希望休以外でシフトが入っていない日。** 期間内のシフトと希望休の取得に成功した場合だけ算出する。新しい休暇テーブルや指定休保存処理は導入しない。未公開の月と確定月を区別する公開フラグは現APIにないため、取得できた予定上の空き日としての表示であり、別途承認済み休暇という意味ではない。

## 再利用元と実装

元はapps/mobile/src/screens/ShiftsScreen.tsxの月7列グリッド。希望休提出タブ、MonthPager、MonthTitle、MonthPickerSheetは維持。新しい確認UIはShiftSchedule.tsxのShiftMonthContent/ShiftDayDetailを通常アプリ・Expo Go・ブラウザで共用。月移動は実機では既存の横スワイプ/年月選択、ブラウザでは月送りボタン。詳細は実機BottomSheet、ブラウザでは隔離モーダル。プレートは既存VehicleIdentity（Web正本SVGから生成した字形PNG・配置）を使用し、新しいフォント描画は追加しない。

本人変更/月変更/再試行時は再取得し、古い非同期応答は反映しない。以前のユーザー非依存のmoduleキャッシュは撤去。月の左右の覗きページは飾りグリッドとし、中心月だけ読み込む。取得失敗を指定休にしない。希望休だけの取得失敗も明示し再読込できる。

## API（ローカル変更・未公開）

/api/me/shiftsの既存の本人向け権限を維持し、以下を追加。DB変更なし、外部操作なし。

- course_name（既存略名）は維持し、course_full_name（正式名）を追加。
- cycle_label、meeting_place、meeting_time、end_time。実効値は既存effectiveTimeにより当日shifts→該当便→コース標準で解決する。
- uses_external_vehicle、vehicle_unavailable、vehicle.plate_color。車両集合は本人の割当済みIDに限定。
- rest_daysは本人のshift_requestsのOFF行から構成し、部分希望休は便名を付ける。便名を解決できなければ「一部の便」。rest_days_unavailableで失敗を区別。
- 指定休は表示側で当該月の日付から算出する。休み情報がない旧APIでは指定休を推定せず取得できていない旨を表示。

配布前にWeb側APIを公開する必要がある。今回は公開していない。通常のWeb版シフト確認UIは改修対象外で、既存レスポンス項目の互換性を維持する。
