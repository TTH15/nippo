# オンボーディングのPasskey優先と新規ユーザーのPIN経路

## 日報からの既存ユーザー移行（2026/09/17 追加）

- 対象: ログインできる既存利用者で、SMS確認またはPasskey登録が未完了の本人。勤務予定・稼働実績の有無では除外しない。利用停止済みの認可を緩める変更は行わない。
- 日報 `/submit` の先頭に未完了の案内を置き、その場でSMS確認・Passkey登録を進める。日報の入力と提出を妨げず、未完了なら次の訪問でも案内する。個別の案内配信はしない。
- SMS送信・検証の番号省略時はサーバーが保存済みの本人番号を使う。明示的な別番号は引き続き拒否。SMS検証と電話番号の保存に成功した場合だけ、同一利用者・セッションに限定した5分の本人確認証明を返し、直後のPasskey登録に使う。証明はメモリ内のみ保持する。
- 戻し方: 日報の案内コンポーネントを外せば既存の日報に戻る。状態取得APIとSMS応答の追加は既存クライアントと互換。既存資格情報・PIN・セッション保存キーを削除せず、データ復元は不要。本番適用前に移行対象者のログイン手段を確保する。
- 以下の初回実装記録で述べるPINの扱いは当時の状態。後続のB-6〜B-8の最終状態は [セキュリティ作業](security-b1-b8-2026-09.md) を参照。

2026/09/17、ユーザー指定の優先作業。招待ユーザーへの初期PIN発行は停止済みだが、Webログインの先頭はPINフォームで、本人プロフィールのPATCHはPIN未発行の人にもPINを新規作成できる状態だった。既存PINのログインAPIとモバイルは稼働しており、PIN全廃済みではない。

## 今回の変更範囲・影響

- 対象: Webの招待/参加登録、登録途中の再開、SMSでのログイン、ログイン画面、マイページのPIN表示、本人のPIN変更API。
- Passkey登録を通常の進み方にする。「あとで設定」の常設ボタンをやめ、設定できない場合にSMSで続行する導線を明示的に開く。キャンセル・失敗は未登録のまま保持し、再試行できる。端末の画面ロックとハコ虎の旧PINを混同する文言を除く。
- 保存済みのPasskeyの有無をサーバーで返し、新規登録だけでなく途中再開でも未登録なら案内する。登録済みの人に重ねて登録を必須にしない。Passkey未対応でも申請/業務を完全に止めない。
- WebログインはPasskeyとSMSを主にし、既存PIN利用者向けフォームは補助導線の中に置く。招待ユーザーにはPINを発行せず、PIN変更APIでも新規作成を拒否する。マイページのPIN変更は既存PINがある本人だけに表示する。
- 既存PINのみの人と旧モバイルのログイン、運営パスワード、セッションの保存キーは維持。全員のPIN無効化やDB更新、ネイティブPasskey導入、Passkey追加/削除の直近本人確認の強化は別工程。今回の変更をPINの完全撤廃とは記録しない。

## 検証・戻し方

- 本番ページと `OnboardingWizard` を使う隔離プレビューで、新規/再開/登録済み/非対応/失敗/再試行をPC・iPad幅・スマホ幅で確認する。SMS・OSの資格情報登録・本番APIを呼ばない。
- PIN未発行のアカウントが直接APIを呼んでもPINを作れないこと、既存PIN変更と本人範囲、Passkey未登録/登録済みの分岐を自動テストする。
- UIで問題があれば対象画面の変更を戻す。PIN新規発行を防ぐサーバー条件は維持する。既存資格情報の削除・新規発行・一括失効は行わないため、データ復元は不要。
- GitHub同期は前の作業の送信承認待ち。今回の認証変更も本番公開・DB更新・通知送信は行わず、検証済み差分とプレビューを用意する。

## 検証結果（2026/09/17）

- 全138ファイル・1,239テスト成功（今回の回帰は22件）。通常の並列実行では既存シフト/貸出UIの2件が5秒で時間切れになったため、CIと同じ `--maxWorkers=2` で全体を再実行して通過。Web・隔離プレビュー・モバイルの型検査、48テーブルの所属範囲検査、`git diff --check` も成功。
- 本番環境ファイルを除いた一時コピーを作り、Node.js 24.21.0・架空のDB URL/キーでNext.jsの本番ビルドを完了（67静的ページ）。本番データは使わない。
- アプリ内ブラウザの1280 / 768 / 390 / 320px幅で本番コンポーネントを監査。招待→SMS→登録案内、未登録からの再開、登録済みのスキップ、非対応時のSMS続行、登録失敗→再試行→成功、読み込み/取得失敗→再取得、申請済みの完了案内、マイページのPIN有無を確認。320pxの横はみ出しはなく、主操作44px・折返し時のSMS続行58px。補助導線はEnterでも開ける。
- SMSログイン後の未登録→登録/再試行→ホーム、登録途中→ `/join` への遷移を確認。PIN未発行の拒否が画面で一般的な認証エラーへ書き換えられSMS案内が消える既存不具合も修正し、回帰テストを追加した。
- UIはSMS・WebAuthnをスタブにし、APIテストはDBモックを使う。実SMSの到達、Safari/iPadOS/Android等のOSダイアログ・資格情報同期、実DB上の認証は未検証。pendingの人がセッションを失った場合のSMS復旧範囲も従来どおりで、今回拡張していない。
- 起動・シナリオ・制限は [プレビュー手順](../development/preview-workflow.md)。`http://127.0.0.1:3199/preview/admin/onboarding?scenario=resumed` を成果物として残す。
