# 管理画面のページ境界と車両ダッシュボード

2026/09/26、管理メニュー全26リンクと本番ページを読み、ページの役割を見直した。提案は表示と導線の整理であり、既存のURL・保存データ・API認可を削除しない。

## ページを分ける基準

- 毎日直接開く、長時間編集する、URLを共有する、保存状態が独立する仕事はページにする。
- 一覧中の一人・一件に対して終わる操作は、一覧から開くダイアログまたはスマホの全画面シートにする。承認待ちの一覧から承認詳細へ進む場合は同じシートの段階を切り替え、モーダルを重ねない。
- 同じ記録の集計・表示軸だけが違うものは、親画面のタブや絞り込みへ置く。
- 設定は対象の画面からも開けるようにし、全社設定の一覧からも探せるようにする。

## ダッシュボードの地図

2026/09/26、実ページ `/admin` に既存 `/admin/map` のMapbox地図本体を組み込み、車種別の3Dモデル、場所・車両移動・履歴の操作を共用した。広域でも車体を小さく表示し、ダッシュボードの初期視点は3D。要対応と今日のシフトは地図の下に置く。車両地図のサイドバーリンクは外し、旧URLは直リンク互換のため維持する。`/api/admin/map/vehicles` の再取得を60秒から15秒へ短縮した。

ダッシュボードでは稼働中・駐車待ち・駐車済み・位置なしを表示する。GPS観測の時刻が退勤後で駐車申告前なら駐車待ち。終了打刻だけで駐車済みとは扱わない。地図の最新位置は既存の `vehicle_positions` を使い、履歴表示も同じデータに従う。

## 業務中のバックグラウンド位置更新

業務の開始成功後に `expo-location` / `expo-task-manager` のバックグラウンド測位を登録し、退勤後も駐車申告が保存されるまで続ける。駐車は日報から独立して保存でき、「日報はあとで」でも完了できる。引き渡しは本人の端末で停止し、「まだ使う」は継続する。ログアウトや認証失効でも停止する。

測位は15秒・30mを目安にし、精度200mを超える点は送らない。送信APIは本人・組織・`purpose=work` のセッション・時刻・座標・精度を検証する。GPS観測は `vehicle_positions` に測位時刻で追記し、同一観測の再送は `client_key` で重複を防ぐ。通信断では端末に最大1,000点を一時保持し、復帰時に再送する。駐車が保存済みならAPIは新たなGPSを受けず、端末のタスクを停止する。端末の強制終了やOS制限では位置更新が途切れるため、実機・署名済みビルドでの検証が必要。

保存期間と軌跡の扱いは未決定。今回の実装は既存の位置履歴に追記するため、公開前に保持期間・削除方針を決める。バックグラウンド権限の審査と実機の長時間・圏外・駐車完了後の停止確認も残る。
