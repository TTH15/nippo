## 確認した流れ

| 操作 | 結果/境界 |
| --- | --- |
| 電話・口座とも未完了 | 電話→OTP→口座。完了済みを省略。外枠/見出し/メインボタンを固定、操作名つきの進捗を表示 |
| 番号の初回入力 | identity/driver両方が空の場合のみ。既存の本人番号を別番号で上書きしない。OTP確認後も最新の番号/未確認状態で比較更新 |
| OTP | 単一input/横6マス。実ペーストした全角6桁も半角各マスに表示。最後の桁のBackspace、誤コードの修正、SMS補完属性を確認 |
| 再送 | 成功から60秒。番号変更/再読込でも待機を保持。失敗時には待機を開始せず、再送成功で古いコードをクリア |
| 口座の初回登録 | 銀行/支店/普通・当座・貯蓄/番号/カナ名義。完全な未登録はパスキー不要。保存済み非空値の書き換えは確認が必要。先頭0を保持 |
| 初回保存失敗 | 入力を保持して再保存。保存後は最新の全項目を照合。保存後取得失敗も未保存と誤認して無確認で上書きしない |
| 登録済み口座変更 | 変更ボタン→パスキー成功→編集→内容確認→保存。中止/検証失敗ではフォームを開かない。説明/完了文は表示しない |
| 専用口座編集証明 | 本人/所属/session/token version/変更前口座へ束縛。5分/1回。汎用reauth/SMS/ログイン証明では代用できず、他端末の変更はhashと比較更新で拒否 |
| 変更の期限切れ/保存失敗 | 入力を保持し、専用パスキー証明を取り直して保存。未保存の取り消しに確認を要求 |
| オンボーディング | 独自OtpSlotsを削除しOtpCodeInputを共用。送信先/変更/再送表示も同じスタイル。氏名・招待・同意・KYC・パスキー登録の既存手順と本番adapterは変更しない |

## 2026/10/14: アプリの口座変更をWebへ案内

更新版アプリに登録口座の確認カードと「Webで口座を変更」を実装。Webの `/account/bank-change` に移り、通常ログインが必要なら成功後に同じ固定パスへ戻る。初回登録モーダルは別の導線として維持。登録済み口座のnative直接保存を廃止したため、更新版のUIに対するP1の変更導線不足は対応済み。既存配布済みアプリはこのコードを適用するまで従来どおりであり、公開はWeb・DB・アプリの順序を調整する必要がある。

Web専用ページはユーザーレイアウトの初回ゲート外で表示するが、口座の読取/変更API・専用パスキー証明・比較更新の認可は維持。アプリのセッションや口座情報をURLへ付けず、同じAPIオリジンの固定HTTPSパスだけを開く。戻り先はこのパスだけを許可し、外部URLには遷移しない。アプリに戻った際は登録済み口座の最新状態を再取得。初回入力中の値はこの復帰処理で上書きしない。

関連Web40テスト、mobile7テスト、Web/mobile/preview型検査成功。隔離ブラウザでアプリ案内ボタン→Web専用ページ、パスキー中止→再試行、編集/確認/保存→My-page反映、未登録では登録先案内、アプリ初回登録→確認カードへの切替を操作。専用ページの320/1280幅で横はみ出しなし・入力48px・初回モーダルなし。実OSのブラウザ起動/アプリ復帰・実SMS/Passkey/DBは未検証。
