# リース契約・ドライバーラベル・シフト表示の仕様案

作成・更新: 2026-08-31 / 状態: 仕様検討中・操作可能なモックあり、本番未実装

ユーザーと合意した内容は「1. 決定事項」に記録する。表示案を試すログイン不要のモックはユーザー依頼により実装済み。「3. 表示案」以降の詳細はモックで検討し、本番仕様の確定・本番適用とは分ける。

## 1. 決定事項（2026-08-31）

### リースの運用上の区分

| 区分 | 運用上の意味 |
| --- | --- |
| 月額リース | 基本的に、特定の車両を継続して借りる人の契約 |
| 日割りリース | 稼働日に会社の車両を借りる人の契約 |

### 月額契約車の一時的な配車

- 紐付けは普段使う車両の目安であり、月額契約そのものや排他的な予約ではない。日額利用者だけでなく、月額契約者同士で貸し借りする場合もある（2026-08-31追加確認）。
- オイル交換・修理中の一時的な代車、月途中からの紐付け変更を扱う。月額料金・普段の紐付け・日別の配車は分ける。
- 貸し出す人の希望休は必須にしない。別車両で稼働する日も、実配車の重複がなく受け渡し可能なら貸せる。二重配車・使用不可の車両・受け渡し未確認は引き続き防ぐ。
- 会社として、この一時的な貸出を活用したい意向がある。
- 貸出可否の確認担当者や詳細な運用は未確定。プレビューは日別配車で一時的な代車を選択し、指定日以降の紐付けは履歴で管理する。

### 一時貸出時の料金

- 一時貸出した日も、月額契約者の料金は据え置き。一時貸出を理由にした減額・還元はしない。
- 借りた日額リースの人には、通常の日額料金が発生する。
- 月額契約者と日額の借り手、それぞれの契約に基づく料金として扱う。
- 給油や車両移動の費用負担・精算方法は、この合意とは別に未確定。
- 月額の借り手に日額料金を自動で追加しない。代車の追加料金・月途中の精算は別途決める。プレビューでは既存の月額契約を表示し、請求を確定しない。

### 将来の要望

- スポットで日額の人へ貸す際に、給油や特定の場所への車両移動を依頼したい。
- 給油の依頼は、日額利用者へ貸し出す前に月額契約者へ満タン給油を依頼するもの。満タンで受け渡し、日額利用者は使用分を補給して満タンで返却する。返却時の給油は任意の貸出前依頼と分けた標準案内とする（2026-08-31追加確認）。費用負担・精算方法は別に未確定。
- その指示を自動で通知する仕組みを将来組み込みたい。モックでは通知文面だけを確認できるようにし、通知の実送信は行わない。
- 受取・返却などの駐車場所は事前に登録し、配車時に選択する。毎回の自由入力にはしない。
- 貸し出す人にも、受取時刻までに受取場所へ駐車するよう通知する。給油依頼がオフでも駐車案内を省かない。借り手の受取先と同じ場所ID・時刻から文面を作る。
- 駐車場所の登録はMapboxで住所検索し、地図にピンを置いて調整できる形にする（2026-08-31追加依頼）。本番登録は未実装。
- 返却時に場所を選択させ、地図UIで車両の所在を管理したい。配車時の予定返却先・駐車場所マスターとは別に、実際の返却記録と車両の地図表示を残タスクとして扱う。

### ドライバーのラベル

- ラベルはすべて並列・同じ重要度とし、1人に複数付けられる。
- 「Amazon」「豊中」は同じ人に両方付きうる。
- 親子関係、優先ラベル、主所属は設けない。「案件」「地域」などの分類階層にも分けない。
- 「Amazon全体」「豊中の人」のような切り口でシフトを見たい。具体的な絞り込み・段分けの操作は以下の提案を基に詰める。

## 2. 現行実装の確認結果

- `driver_leases` の `MONTHLY` はドライバー別の固定額、`DAILY` はコースの `daily_lease` を稼働日ごとに控除する。同日の複数コースは最大日額を1回採用する。
- 現行の控除計算は報酬集計の日別実績を使い、シフト予定そのものでは課金しない。日割り単価はドライバー別ではなくコース別。
- 設定画面の表示は「リースなし／月額／日毎」、適用開始は月単位。期間をまたぐ集計では最新の契約1件を採用するため、月途中の契約切替を日別に計算する仕様にはなっていない。
- リース契約と車両紐付けは別の情報。`driver_leases` に対象車両はなく、`vehicle_drivers` とシフトの `vehicle_id` で紐付け・当日の配車を扱っている。
- 既存の `vehicle_loans` に登録された車両は、その日のシフトへの配車が禁止される（`apps/web/src/app/api/admin/shifts/vehicle/route.ts`）。今回の社内での一時貸出をそのままこの仕組みに登録する設計にはしない。どの既存情報を再利用するかは実装設計で決める。
- シフト画面にはドライバー軸・コース軸がある。現在のドライバー行は担当可能コースのある人を名簿のNo.順で表示し、リース区分・自由ラベルは取得していない。

参照: `apps/web/src/server/billing/driverLease.ts`、`apps/web/src/app/api/admin/driver-lease/route.ts`、`apps/web/src/app/api/admin/shifts/route.ts`、`apps/web/src/app/(admin)/admin/(ops)/shifts/page.tsx`、`docs/database-schema.md`。

## 3. 表示案（未確定）

### ラベルと契約を別々に扱う

- 共通ラベルの追加・名前変更・削除はドライバー一覧内で行い、独立した管理ページは設けない。
- ラベルは会社ごとの共通一覧から複数選択する。ラベル名の自由入力を各ドライバーで繰り返す運用は避ける。
- リース区分は契約から自動表示し、「月額」「日割り」を手動ラベルとして二重管理しない。
- ラベルの変更で契約金額、担当可能コース、実際のシフト割当、権限は変わらない。コースやキャリアからの自動付与も初期版には入れない。

### シフトの絞り込み

2026-08-31の追加要望に合わせ、ラベルはトグルで複数選択する案へ更新。選んだラベルのいずれかに一致する人を表示する（OR）。ドライバーへのラベル付与そのものは変更しない。

| 選択 | 表示対象の例 |
| --- | --- |
| すべて | ラベルがない人を含む、シフトの表示対象者全員 |
| Amazon | Amazonラベルがある人。豊中も付いている人を含む |
| 豊中 | 豊中ラベルがある人。Amazonも付いている人を含む |
| ラベル未設定 | ラベルが1つも付いていない人 |
| Amazon ＋ 豊中 | どちらかのラベルがある人。両方ある人も1行だけ |
| Amazon ＋ ラベル未設定 | Amazonの人と、ラベルがない人 |

- 「豊中だけを見る」は豊中ラベルを持つ人への絞り込みであり、他のラベルもある人を除く意味にはしない。
- 選択済みのラベルをもう一度押すと解除。「すべて」または全解除でラベル条件なし。ANDへの切替、階層フィルター、任意条件の保存は今回の案に含めない。
- 契約の選択と「契約区分でまとめる」を隣に置き、検索欄はその後に配置する。3つの操作は高さ44pxで揃える。
- リース区分の絞り込みは別に置き、ラベル条件と組み合わせる（例: Amazonラベルがあり、月額契約の人）。
- 人を絞り込んでも、その人の別コースの予定は隠さない。ラベル未設定を理由に既存の表示対象者を除かない。
- コース未登録者の表示範囲を広げるかは別論点とし、ラベル追加に混ぜて変更しない。

### 一覧の段分け

- ラベルで絞り込んだ後、「まとめない／リース区分でまとめる」を切り替える案。
- リース区分でまとめる場合は「月額／日割り／リースなし」。各段の中は名簿のNo.順を維持し、1人を複数行に重複表示しない。
- 名前の横にラベルとリース区分を表示する。契約金額の表示は別途閲覧権限を検討し、初期案では出さない。
- ラベル別の段分けは初期案に含めない。複数ラベルを持つ人の重複表示や優先所属を必要とするため、まずラベルの切替で対応する。
- スマホは日別表示とし、前半／後半はPCだけに残す。「全員／稼働／未割当」の人数付きタブを維持し、未割当には希望休を含む。日別PNGは選択中のタブ・ラベル・契約・名前の条件と表示項目を反映し、ドライバー順に出力する。コース軸専用の画像と半月表の画像/PDFは今回のプレビュー対象外。

### 月額車の一時利用・代車と紐付け変更

- **月額の契約者・契約車両**と、**その日に借りる人・貸出期間**を別々に記録する。一時貸出のために月額契約やドライバーのラベルを切り替えない。
- 通常の配車操作で空いている月額契約車を選ぶと、「月額リース車両であること」と「利用者に通知する内容」の確認モーダルを表示する。配車セルの日付・利用者・車両を引き継ぎ、確認して確定する。独立した貸出ページや再入力は設けない。権限・本番での送信方法は別途検討する。
- 希望休・未割当・別車両での稼働を理由に貸出を一律に止めず、実配車の重複と車両の使用可否を検証する。確定操作で受け渡し・次の利用への支障がないことを確認する。
- 一時貸出は「いつ・どの車を・誰から誰へ・どこで受け渡し／返却するか」が分かる形にする。月額契約者と一時利用者の両方を確認できる表示を検討する。
- 一時貸出を取り消しても月額契約は維持する。日額の借り手には通常の日額を参考表示し、月額の借り手は月額契約と追加料金・精算が未確定である旨を表示する。配車予定の保存だけでは課金しない。
- 普段使う車両はドライバー一覧で変更日を指定する。変更前と次の変更予定を保持し、既存の配車を自動で書き換えない。同じ車両への複数人の紐付けや紐付けなしは許可し、実配車の重複防止とは分ける。
- 紐付けから貸出側が1人に決まる場合は初期値にし、複数なら明示選択する。貸出側は確認モーダルで変更可能。保存した貸出側・利用者の契約区分を保持し、その後の紐付け変更から通知先を再推定しない。

## 4. 給油・移動指示の通知案（将来・未確定）

通知文だけを保存するのではなく、一時貸出に付随する指示を記録し、その内容から通知を生成する案。

| 指示 | 決めておく内容の例 |
| --- | --- |
| 貸出前の給油 | 月額契約者へ、貸出前に満タンで引き渡すよう依頼。費用負担・精算は未確定 |
| 返却時の給油 | 借りた利用者が使用分を給油し、満タンで返却する標準案内 |
| 車両移動 | 担当者、移動先、到着期限、必要な受け渡し情報 |

- 「貸出前の満タン給油を依頼する」をオンにした場合、「依頼する相手」は月額契約者、「依頼する内容」は満タンでの引き渡しを初期値にする。新規配車の依頼は初期オフ。必要に応じて他の登録ドライバーにも変更できる。利用者と依頼先が別なら、配車・受け渡しの通知と貸出前の給油依頼を宛先ごとに分ける。同じ人なら一通にまとめ、通知対象をラベル所属者全体へ広げない。移動連絡は現在のモックでは利用者宛てとし、担当の分担は別途検討する。
- 貸出前の依頼をオフにしても、利用者への「使用分を給油し、満タンで返却」の標準案内は残す。給油担当者への依頼には利用者の返却時給油や任意連絡を混ぜない。貸出側には別途、駐車場所・期限を常に案内し、同じ人への給油依頼はその文面にまとめる。
- 貸出内容と指示を確定した段階で通知を生成し、必要な時刻に配信する案。入力中の変更のたびには送らない。
- 既存の通知設計（`docs/notification-flow.md`）は、シフト変更を差分表示して運営が明示送信する方針。一時貸出の自動通知を追加しても、通常のシフト変更通知の挙動は勝手に変えない。
- 配車先・日時・指示の変更や貸出取消時は、古い予定の通知・リマインドを止める。同じ指示を重複送信せず、伝達済みの場合は訂正・取消の連絡を検討する。
- 通知済み・既読と作業完了は区別する。将来、完了報告や未完了時のリマインドを入れるかは別途決める。
- 関連する設計案は `docs/vehicle-session-flow.md` の給油・移動記録、`docs/parking-location-flow.md` の駐車位置。これらがすべて実装済みとはみなさず、連携時に現行実装を確認する。

## 5. 次に決めること

1. **一時貸出の確認**: 貸出可否の確認者・方法、受け渡し・返却条件、代車運用。給油・車両移動の費用負担はリース料金と分けて決める。
2. **日割りの課金根拠・例外**: 通常の日額料金を使う方針は確定。現行のコース別日額と稼働実績による計算を継続する前提で検討し、会社の車を使わない稼働日、日中の車両交換などの扱いを詰める。
3. **契約の期間**: 開始・終了・切替、月途中の精算、休業時の免除。過去や未来のシフトを開いたとき、表示期間のどの日の契約でまとめるか。
4. **名称**: 「日額リース」への統一案。稼働日課金の契約と、月額契約の途中開始による日割り精算を区別する。
5. **表示・管理**: 上記の絞り込み案、ラベルの作成・付与権限、名称変更・廃止、過去シフトでのラベルの扱い。

進め方の案: ラベル付与・契約区分の表示・シフトの絞り込みと段分け、契約車両・一時貸出をモックで確認する。給油・移動の自動通知は将来の拡張として分ける。本番の実装範囲はまだ確定していない。

本番用の画面・保存API・日報・契約控除・車両回収・通知・地図を調査し、[本番反映の調査と段階別手順](driver-leases-production-rollout.md)に記録した。特に、既存vehicle_loansは社外貸出／当日の配車禁止に使われ、本番の同日車両共有は確認後に許可するため、モックの制限をそのまま本番仕様にしない。会社境界の検証不足と契約保存失敗の扱いを、リース機能を広げる前に修正する。今回は調査までで、本番用ページ・API・SQL・実データ・通知は変更していない。

### 車両選択の基本UI（2026-08-31）

- 車両は文字列のセレクトではなくナンバープレートを見て選ぶ。配車画面の既存プレート一覧を維持し、ドライバーの「普段使う車両」も選択中・候補とも共通VehiclePlateで表示する。
- 通常は選択中だけを表示し、変更時に共通SmoothCollapseで候補を開く。PC3列／スマホ2列、番号・車種で検索でき、選択状態は背景・枠で示す。チェック用の余白を作らない。
- 「紐付けなし」と整備中の注意表示を維持。車両の紐付け・配車の保存条件と料金計算は変更しない。本番移植時もこの選択形式を標準とする。
