# 文書プラットフォーム — テンプレ+差し込み路線の決定記録

作成: 2026-08-13。ステータス: **方針承認済み(2026-08-13 ユーザー決定。実装は未着手)**。
発端: 「Google Docs や Word の、マクロや図形描画などを省いたものぐらいまでできると、
必要な文書はすべてハコ虎上で制作・管理できてありがたいが、保守コストが見合わないなら考えもの」
→ 検討の結果「テンプレ+差し込みがベター。契約書も条文を input で入力させて、
PDF 出力したい時だけできるようにする方がいい。オンラインで契約するなら A4 にする必要もない」(2026-08-13)。

## §0. 決定(3行)

1. **自由編集の文書エディタ(Docs-lite)は作らない。** 文書は「テンプレート + 差し込みデータ +
   最小限の自由記述欄」で表現する。
2. **正本は構造化データ、A4/PDF はビューの一つ。** 画面表示はスマホで読みやすい連続スクロール、
   A4/PDF は「印刷・送付したい時だけ」のエクスポート形式に降格する。
3. **契約書をこの路線でハコ虎上で作成できるようにする。** これが次の実装対象(§3)。

## §1. 経緯と判断材料

- 既存の「帳票エンジン」: 請求書は React 製 A4 帳票(`InvoiceSheet`)+ payload(jsonb)正本 +
  `@media print` + jsPDF で本番運用中(docs/invoice-react-migration.md)。
  **「決まった様式にデータを流し込む」用途では実用ラインに達している。**
- Docs-lite(Word/Docs 代替)には3つの沼があり、1人保守では見合わないと判断:
  1. **日本語 IME × contenteditable**。既に入力欄の定義位置だけでフォーカス喪失・IME 不能の
     地雷を踏んでいる(invoice-react-migration.md §2)。まともにやるなら ProseMirror/Tiptap 等の
     エディタ基盤が必須になる。
  2. **Word 型ページネーション**(画面上で A4 ページに割りながら編集)は HTML/CSS の最も苦手な
     領域。Google Docs 自身が DOM を捨てて canvas 描画に移行したほど。
  3. **PDF 品質**。html2canvas+jsPDF はラスタ PDF(選択・検索不可)。文書管理基盤の出力としては弱い。
- 外部リサーチ用プロンプト(docs/prompts/document-editor-research.md)で他 AI にも確認の上、
  ユーザーが「テンプレ+差し込みがベター」と結論(2026-08-13)。
- 傍証: 7月チーム戦レポート(2026-08-13)で「HTML+印刷CSS → ヘッドレス Chrome で PDF 生成」の
  手順を確立。A4・6ページ・改ページ制御ありのテキスト PDF が問題なく出せた。
  ※このとき claude.ai の iframe 越し印刷では改ページ制御が一切効かないことも実証済み
  (iframe 内容は機械的にスライスされる)。**PDF はトップレベル文書として印刷させるのが原則。**

## §2. アーキテクチャ原則

| 層 | 方針 | 実装の当て |
|---|---|---|
| 正本 | 構造化データ(jsonb payload)。テンプレ ID + 差し込み値 + 自由記述欄 | `invoice_documents.payload` と同型 |
| 画面 | React の連続スクロールビュー(スマホ優先)。A4 の紙面再現はしない | 既存の帳票コンポーネント様式を流用 |
| PDF | 必要時のみのエクスポート。印刷CSS + サーバ/ローカルの Chromium 印刷(テキストPDF) | 7月レポートで確立した手順。将来はサーバ側 Playwright 化も可 |
| 自由記述 | 当面 textarea + 改行表示で十分。太字・箇条書きが実務で必要になってから Tiptap 等を「1コンポーネント」として最小導入 | 全画面エディタにはしない |
| 記録 | 電子契約の本質はレイアウトではなく**同意の記録**(誰が・いつ・どの版に同意したか) | 同意ログを一級市民に(§3) |

やらないこと: フル自由編集の Docs-lite / Quarto・Typst 等の別組版ツールチェーン導入 /
画面上のページネーション付き WYSIWYG。

## §3. 次の実装対象: 契約書(方針のみ・スコープは着手時に別途)

**進めることが決定済み(2026-08-13)。** ハコ虎上で契約書を作成・管理できるようにする。

- 想定モデル(たたき台。着手時に要検討):
  - `contract_templates` … 条文構成とバージョン。条文 = 順序付きの節(見出し + 本文 + 差し込み変数)
  - `contract_documents` … テンプレ参照 + 差し込み値(当事者・金額・期間など)+ 条文の上書き/追記。
    正本は payload(jsonb)
  - 同意ログ … 誰が・いつ・どのドキュメントのどの版に同意したか(タイムスタンプ)。
    オンライン契約はこれが本体で、紙面は付随物
- 条文の入力は input / textarea(§2 の方針どおり、リッチテキストは必要になるまで入れない)
- PDF 出力は「出力したい時だけ」のボタン。オンライン完結の契約では A4 を経由しない
- 流用資産: 請求書の payload 正本パターン / 帳票ビューの様式 / `@repo/core` への計算・検証ロジック
  集約とテスト / 印刷CSS と Chromium 印刷手順
- 雇用条件通知書・社内通知など他の定型文書も、契約書で型ができたら同じ仕組みに載せる
