## 操作の流れ

1. Base/adminから移動担当に指定された本人のホームにだけ「車両の移動」を表示し、QRを読み取る。既存CaptureFlowの読み取り・認可・読めない場合の経路を再利用する。2026/09/25時点の通常ホーム試作では入口を非表示にしており、管理画面の担当設定と開始APIの認可は後続実装。
2. 対象車・依頼された移動先/期限/給油の有無を確認する。依頼なしの移動も想定し、行き先は未設定を許す案。QRだけで他社車の利用権を与えない。メーター・点検の必要条件は既存運用を確認して継承する。
3. 位置の共有先と記録期間を短く示して権限を要求。「移動開始」の明示操作で `purpose=move` の開始に成功した後、位置記録を開始する。読み取っただけでは追跡しない。
4. モーダルに「車両移動中」、車番、行き先、位置記録状態、必要なら「給油を記録」、主操作「移動終了」。閉じるとタブ上のミニバーになり、移動セッション/位置記録は続く。
5. 到着して「移動終了」→メーター・給油確認・駐車/引渡し→同じ車の確認→終了を保存。仕事の日報を要求しない。駐車位置が取れなくても移動終了を保存できる案。
6. 依頼先に着いたことを確認できた場合だけ手配を完了にする。違う場所なら実移動は終了できるが手配は未完了。自動GPS到着だけでセッションを終わらせない。

稼働と移動の同時開始は不可。既存の本人open制約を両用途に適用し、車両側の他者利用競合もサーバーで確認する。稼働中の「車両交代」をmoveへ自動転用しない。移動時間/距離は別用途で記録し、仕事の日報・稼働集計へ自動加算しない。回送の報酬/精算方針は別途決める。

## 位置追跡の範囲と失敗

- 移動セッション中だけ取得。通常ホーム・通常稼働・私用では新しい連続追跡を起動しない。本人と車両所在を見る権限のある同一運用範囲の運営へ共有する案。別ドライバーへの軌跡公開は初期範囲に含めない。
- iPhoneで画面ロック/地図アプリへの切替中も記録する要件として設計する。`expo-location` + TaskManager、iOSのbackground location権限/設定が必要。Expo Goの画面確認と、署名した開発ビルドでのバックグラウンド検証を分ける。[Expo SDK57 Location](https://docs.expo.dev/versions/v57.0.0/sdk/location/)、[TaskManager](https://docs.expo.dev/versions/v57.0.0/sdk/task-manager/)。
- 秒単位の追従ではなく、初期案は移動距離50〜100m相当の更新とまとめ送信。OSが実際の頻度を制御するため、指定間隔を保証しない。実機で電池/精度/空白を測り調整する。
- `tracking = active / foreground-only / denied / interrupted / ending / stopped` をセッション・モーダルとは別に持つ。位置が古ければ時刻と「位置情報が更新されていません」を表示し、追跡中と偽らない。
- 権限拒否/途中取消/低精度/圏外でも移動記録の継続・終了を塞がない案。位置取得の再試行・手動の到着場所を使う。モーダル閉鎖/タブ切替では追跡停止せず、明示終了・ログアウト・権限取消では止める。
- 終了操作時に端末で追跡停止と終了意図/時刻を永続化する。通信不能なら「終了を送信待ち」。失敗で追跡を自動再開せず、冪等キーで終了保存を再送する。開始時の応答喪失も本人openを照合し、二重開始しない。
- アプリ強制終了やOSによる停止では記録が途切れる。バックグラウンドで無期限に必ず追跡できるとは扱わない。復帰時にサーバーopen、端末終了待ち、OSタスクを照合する。古いopenだけを根拠に利用者に知らせず追跡を再開しない。
- 未送信点はセッション/本人単位で保管、上限/有効期限を設定する。ログアウト・別ユーザー切替で新ユーザーの認証を使って送らない。遅れて届いた点を新セッションの現在地にしない。
- GPS点は移動中の最終観測位置として管理し、「最後に駐車した場所」とは区別する。駐車/引渡しを確認した終了地点だけ共通の駐車履歴へ渡す。位置失敗で退勤・日報を止めない既存原則も継続する。

軌跡の保存期間、閲覧権限の具体名、手動位置記録を許す条件は公開前に確定する。未確定のまま本番で連続位置を蓄積しない。モックはブラウザの位置権限すら要求せず架空座標を使う。

## 給油を促す条件

**ユーザー決定: 移動依頼で「給油あり」と指定されたときに促す。** 全移動で満タンを要求したり、残量の自己申告を必須にしたりしない。スマホのGPSから残量は分からず、推定残量を実測のように表示しない。

- 「給油あり」の開始確認と移動モーダル内に給油タスクを示す。指定なしでは給油を促すタスクを出さない。手動での給油記録入口は残す案。依頼が変更されたときは版で検知し、黙ってタスクを消さない。繰り返し音や走行中の強制入力で促さない。
- 給油は「給油を記録」から、日時・給油量・金額・レシート・満タンかを必要範囲で記録。車両/移動セッションに紐付け、仕事の日報提出を前提にしない。
- 未給油のまま終了する場合は「今回は給油していない」等の理由を残す案。給油したことにして終了させる制約は作らない。終了後の修正履歴も残す。
- ガソリンスタンド付近にいることだけで給油済みと認定しない。位置から燃料種類も推測しない。近隣スタンド検索/ルート案内/外部通知は後続範囲。
- 費用負担・返却時満タン・精算先は `driver-leases-and-labels.md` の未確定事項と合わせて判断する。

## サーバー変更案

既存開始/終了/QR認可を拡張する。新規API名・テーブル名は仮であり、この文書だけでmigrationを適用しない。

- `CheckInBody.purpose` の追加と用途別文言。`/api/work/today` のDBエラーは成功の空値として返さず、openの不明を通知する。HomeViewModelはwork/move/privateを分ける。
- 本人と車両のopen一意性をDB/トランザクションで保証し、開始・終了の冪等キーを導入。用途をクライアントの後付けラベルだけで切り替えない。
- 移動手配IDとの関連、行き先/給油指示のスナップショットをセッションに紐付ける。既存 `vehicle_movements` をGPS点の保存先にしない。
- 位置バッチAPI案 `/api/vehicle-sessions/:id/locations`。本人・org・purpose=move・許可期間・記録端末を検証し、イベントID/連番で重複排除。座標範囲、精度、時刻、件数/頻度の上限をサーバーで検証する。任意車両IDを指定して送らせない。
- 完了後の遅延点は、終了時刻以前の点だけ許容期間内で受理する案。最後の観測時刻より古い点で地図の現在位置を巻き戻さない。次の利用が始まっていたら旧セッションの点で上書きしない。
- 給油イベントはセッションと車両へ保存。既存の精算経路との重複を確認し、リトライで二重請求を作らない。今回独立した給油API/残量センサー連携は確認できていない。
- 終了と、確認した駐車/手配到着の保存整合性を保証。地点保存失敗は明示し、セッション終了を無限にやり直させない。
