# シフトメモから正式シフトへの反映

2026/09/15、ユーザーの依頼により実装。本番公開・migrationの適用は未実施。

## 操作

- 本番の `shifts/page.tsx` と `PersonalShiftMemoBoard.tsx` をそのまま再利用し、メモ上部に「シフトへ反映」を追加。通常のメモ編集・端末への自動保存は従来どおり。
- 表示期間の開始日・終了日と担当枠を選択する。初期状態は担当枠未選択。非表示の担当枠も明示的に選べる。
- 既定は「今のシフトに追加」。同じ日・コース・便の既存配置は保持する。「メモに合わせて入れ替え」を選ぶと、対象の便では選択した担当枠にいない人を解除する。差分を表示してから確定する。
- 空白日は既定で対象外。「配置のない日も空にする」を選ぶと、その範囲の配置を解除できる。個人メモの休み／必要人数そのものは正式シフトの設定に転記しない。
- 便のあるコースは、従来の標準枠IDからC1/C2を復元する。独自枠は便を明示的に選ぶ。「すべての便に同じ人を配置」も選べる。同じ便へ複数枠から入る同じ人は1人にまとめる。
- 自由な名前札・登録がなくなった人は、既定ではメモだけに残して正式シフトへ反映しない。登録ドライバーへ反映したい場合だけ明示的に対応を選ぶ。氏名から推測して登録先を決めない。非稼働日に札が残っている場合はメモの修正を求める。
- 担当枠の配置場所（親コース）と正式な反映先コースは別に選ぶ。自作枠は名前が登録コースと一意に一致した場合のみ初期候補とし、曖昧な枠は選択を必須にする。確定した反映先はメモの担当枠へ保存する。
- 希望休と別コースの配置は警告して確認する。同じコースのC1/C2兼務は重複扱いにしない。
- 反映後もメモは残る。シフト表を再取得する。反映自体が成功し再取得だけ失敗した場合は、その旨を表示して再取得だけを試せる。

## 保存・権限

- `POST /api/admin/shifts/memo/reflect`。`action=preview|apply`、`mode=add|replace`、対象は `{date,courseId,cycleNo,driverIds[]}[]`。両actionとも `can_manage_shifts` 必須。
- 会社・実行者は認証から取得。`reflect_shift_memo` RPC（migration 165）内でも、自社の有効なコース・便・稼働中ドライバーを全件検証する。RPCの実行はservice_roleのみ許可する。
- previewはDBを書き換えない。入力、対象期間の自社シフト、希望休、コースの状態からrevisionを作る。applyは同じrevisionを要求する。
- applyでは `shifts` に短時間の `SHARE ROW EXCLUSIVE` ロックを取得する。通常編集・インポートも含む書き込みが競合しても、確認後の配置・車両変更をrevisionで拒否する。ロック待ち5秒、処理20秒の上限。対象外コースも含め自社の同期間が変わった場合は再確認になる。
- 配置が同じ人のslot・車両・個別時刻・取込元は保持。解除行はドライバー・車両・個別時刻・取込元をクリア。新規配置には配車設定のない空枠だけを再利用し、配車だけが残る既存の空枠は保持する。
- 配置と `shift_change_logs` を同じトランザクションで保存する。ログ書き込みが失敗しても配置全体をロールバックする。通知送信は追加していない。
- 入力上限は2,000日×便の組・5,000配置・62日。確認なしの確定、不正日付、重複、異なる会社のIDを拒否する。

## 隔離プレビュー

`npm run preview:admin -- admin --port 3215`

入口: `http://127.0.0.1:3215/preview/admin/shifts?scenario=normal&role=admin`

既存の単独shifts runnerと別に、標準admin runnerへ `scripts/previews/fixtures/shifts.ts` を登録した。本番ページ・ロゴ・ナビ・表・編集部品を再利用し、API・認証・同時編集通信をfixtureへ差し替える。架空の氏名・コースだけを使用し、本番のDB・API・通知へは接続しない。シナリオ切替・再読み込みで架空状態とプレビュー用利用者のメモを初期化する。

normal / empty / long-name / large / loading / error / conflict / save-error / unmapped と、admin / accounting / viewer を用意。反映の保存先は画面内のfixture。必要人数はプレビュー利用者専用のlocalStorage。

2026/09/30に `transfer` シナリオを追加。親コースと異なる反映先を持つ自作枠、登録外の名前札、端末間受け渡しの操作を本番のメモ画面で確認できる。個人メモのデータファイルは端末内で解析し、プレビューでは架空データのみを扱う。

## 個人メモの端末間受け渡し（2026/09/30）

- 上部の「読み込む」からJSON・PNG・PDFを選ぶ。JSONは盤面全体を復元し、PNG/PDFは読み取った行と日付の名前札を確認して個人メモへ取り込む。エクスポートでは範囲を選んだ後、PNG・PDF・CSV・JSONを同じ形式選択欄に並べる。CSV・JSONはメモ全体を書き出す。JSONは端末間の完全な受け渡し、CSVは表計算での確認に使う。
- JSONは端末内で形式・担当枠・コース所属・配置を確認する。異なる会社のコースを含むファイルは拒否する。現在の登録ドライバーにない名前は、ログイン権限を作らずメモの名前札として保持する。
- JSONの件数を確認してから、この端末の個人メモを置き換える。置き換え直前の盤面を端末内に退避し、「読み込み前に戻す」で復元できる。共有メモや正式シフトはこの操作で変更しない。
- PNG/PDFは既存の画像読み取り基盤へ送って行・名前札を抽出する。保存前に元ファイル・候補を表示し、各行の読み込み先を既存枠・新規枠・除外から選ぶ。対象セルの配置だけを置き換え、読み込み前の個人メモに戻せる。読み間違いの確認は利用者が行う。端末間の自動同期と他社データのコース変換は対象外。
