# 日報と一緒に送る選択項目（設計案）

2026/10/17。汎用化の方針整理のみ。DB・入力機能は今回作成しない。

- 管理側が「使用コード」「稼働名義」「応援区分」などの項目名を作り、選択肢を管理する。ヤマト固有のテーブル名・カラム名・必須仕様にしない。
- 選択肢には内部ID、表示名、任意の番号、任意の名義人、利用可能な会社・コース・期間を持たせる。入力時は表示名と番号・名義人を並べ、当日・対象コースで使える候補だけを出す。番号の自由入力で送信させない。
- 実際に走った本人と、選択肢の名義人を分ける。本人のログイン所属・計算対象ドライバーを、コード名義へ付け替えない。
- 選択の単位を日単位／コース・便単位で管理側が指定する。通常の割当を候補の先頭に置けるが、借用や途中変更を無言で確定しない。必須の範囲と代理入力時の扱いを決める。
- 日報には選択肢IDと送信時の表示内容を保存し、後日の名称変更・利用停止でも履歴の意味を保つ。候補の削除は過去の提出値を消さず、新しい入力だけから外す。
- 送信時に会社・対象コース・利用期間・有効状態をサーバーで再確認する。古い画面の候補が無効なら入力を保持し再選択へ戻す。未確認の候補を「その他」の自由入力で計算へ通す運用は採用しない。
- 日報確認では予定の割当と実際に選択されたラベルを併記する。一致は番号文字列だけで判断せず、安定した選択肢IDと有効な割当で照合する。

着手前に整理する点: 借用を許す範囲、当日途中でコードを変えた場合の単位、候補にない時の申請先、名義人の閲覧範囲、既存の勤務区分（driver_identities）から移行する対象と過去データの扱い。
