# ログイン入口の設計（2026/09/29）

## 方針

同じ本人アカウントを使う。PCではドライバー画面と運営画面の入口を選び、スマホではドライバーログインを直接表示する。運営画面はPasskey必須。電話番号はドライバー画面へのログインとPasskeyの設定・復旧に使う。PCの入口には「ドライバー」「運営」以外の説明や管理者ロール名を置かない。

## 画面

- 本番 `/login/page.tsx` を隔離プレビューでも直接使う。実画面のハコ虎ロゴとslate・amberのブランド色を継承する。
- 全画面を明るい軽バンの現場写真と、暗い小規模配送拠点の写真で二分する。境界は黄色の斜線で、選んだ側へ620msで滑る。写真に文字やボタンを焼き込まず、HTMLのラベルと認証操作を重ねる。
- PCは左右二分。キーボードで両側を選べ、`prefers-reduced-motion` では補間を止める。スマホは軽バン写真とドライバーログイン操作を直接表示し、二分画面や切替アニメーションは置かない。
- スマホの通常ログインに「ドライバー」の見出しは置かない。Passkeyと電話番号を「または」の細い区切りで分け、電話番号も枠付きの独立したボタンにする。運営の設定・復旧は代替ログイン手段ではないため、区切りを置かない。
- 明るい側は軽配送用の軽バン、暗い側は配車表・小口荷物・軽バンのある拠点。写る事業用軽バンの前後ナンバーは黒地に黄色文字。出所は今回生成した架空写真で、`apps/web/public/login/` に置く。
- PCの初期状態は画面選択のみ。選択後にその側の認証操作を表示し、「選び直す」で最初の二分画面へ戻る。認証カードは不透明な面とし、写真との境界にブラーを使わない。

## 認証と遷移

| 入口 | 主操作 | 補助操作 | Passkey成功時 |
| --- | --- | --- | --- |
| ドライバー | パスキーでログイン | 電話番号でログイン | `/submit` |
| 運営 | パスキーでログイン | パスキーを設定・復旧する | 運営権限を確認して `/admin` |

- PCの `/login` は入口選択。スマホの `/login` と `/login?next=driver` はドライバー認証を直接表示する。`/login?next=admin` は、運営画面から認証を求められた場合に運営用Passkeyを直接表示する。`/admin/login` は後者へ転送する。
- スマホのドライバー画面内にある権限保持者向け「運営画面」ボタン（`ModeSwitchFab`）を入口として使う。別アカウントを作らず、運営用トークンがない場合はPasskeyを求める。
- Passkeyの認証APIは既存のものを使う。選択先による遷移以外に、発行トークンや権限の判定は緩めない。運営権限なしは画面内エラーとし、運営には進めない。
- `next=admin` のSMS復旧は業務セッションだけを発行し、登録状態を確認する。未登録ならPasskey設定を必須にし、登録後は `/login?next=admin` でPasskeyログインする。登録済みなら同じ入口へ戻る。SMSだけで運営画面へは入れない。
- Passkey非対応のブラウザではSafariまたはChromeを案内する。SMSで業務セッションを得た人はドライバー画面へ進める。
- 保存済みlocalStorageキー `nippo_token` / `nippo_driver` は変更しない。運営の短命JWTが切れても業務セッションは維持する。

## プレビュー

`npm run preview:admin -- admin --port 3230` で起動し、`http://127.0.0.1:3230/preview/admin/login?scenario=normal&role=admin` を開く。`next=driver` / `next=admin`、利用停止・運営権限なし、SMS復旧、PC幅・390/320px、キーボード操作を確認する。プレビューは本番ページ本体と架空の認証応答・写真を使い、実SMS・OSのPasskey・本番API・DBには接続しない。

2026/09/29にPR #53を`main`へ統合し、Webのログイン画面を本番公開した。モバイルアプリ画像のネイティブ配布と、実ユーザーのPasskey・SMS操作確認は別途行う。
