# 終了後の日報と完了ホーム（2026/09/23）

- 再利用元: `NativeHomePreview.tsx` のHome/Finish、実アプリの `src/components/DailyReportForm.tsx`。ブラウザも同じ日報フォームをDOMアダプターで描画し、原本画像ピッカーだけを送信しない表示スタブへ置換。
- 終了撮影を送信すると稼働終了。続いて割当コース/便の日報フォームを開く。日報POST成功後だけ「お疲れ様でした」「日報 送信済み」「次の稼働」を表示。ホームに車両3D/当日のコース/開始リボンを出さない。
- 日報を閉じた場合は「稼働は終了しました」「日報が未送信です」と再開入口。送信エラーでは入力を保持して再送。タブ内の日報からの成功でも完了へ進む。
- 駐車は独立状態で、日報完了ホームから記録を続けられる。位置未確定・駐車未記録は日報完了を妨げない。車両移動の終了から日報へは進まない。
- 次の予定はシフトfixtureと同じ架空日付（当日から2日後）。ネイティブ設定/ブラウザ確認欄で予定なしを試す。
- 起動: `node scripts/serve-mobile-preview.mjs --port 3202`。完了は `?screen=home-design&board=ribbon&state=done&revision=end-of-day`、日報入力は `state=end-report`、終了撮影から試す場合は `state=working`。
- 検証: mobile型、33テスト。ブラウザ1280/768/390/320pxで終了の全撮影→実フォーム→送信エラー/値保持→再送成功、次の予定、予定なし、タブ往復、送信済み日報の再読込、未送信でホームへ戻る/再開。横はみ出しとJSエラーなし。
- Simulator: 開始・終了それぞれの全撮影→割当コースの日報入力→送信エラー→再送→完了→シフト往復→予定なし。経路と画面を確認。画像はSimulatorと別プロセスのローカルChrome。Codexアプリ内のopen要求はqueued。
- 未検証/制限: 実iPhoneの今回の操作。本番API接続、複数便/追加稼働、実際のシフトの次回抽出、再起動・日付変更時の完了復元は後続。試作の状態/架空日報はメモリ内で、再読込すると初期化。日報の実保存・DB変更・外部公開なし。
