# スクロール競合の解消・触覚（2026/09/23）

- nativeのHome/RibbonControl/Active/SettingsをSimulatorで撮影。browserは同じ構成をSessionShellReviewで複製。青い歯車はExpo Goの開発用表示。
- ホームをコンパクトにし、駐車カード全体を地図への入口にした。確認用条件を設定へ移動。通常サイズでは全操作を表示し、小画面・大文字・駐車候補通知で必要なスクロールは残す。
- つまみでtouch開始時から操作を確保。親ScrollViewは一時停止し、縦ずれは取消条件から除外。OS中断・背景化・指の追加・途中解放は引き続き取消。戻るとスクロールを復旧。
- 実機の終了スライドでiOS formSheetのpan競合が残ったため、ActiveをtransparentModalに変更。ハンドル限定案はユーザーの希望で撤回し、SessionSheetでリボン以外からの下ドラッグ追従を実装。内容が先頭のときだけモーダルが動き、途中は内容のスクロールを優先。nativeタブ・下向きボタン・ミニバーを維持。
- Light impactを開始・移動量1/8の節目・解放、Mediumを終端で使用。節目は65ms以上空け、終端の反応は1操作1回。振動オフでは発火しない。遅延振動の予約なし。
- 「設定 → スライドの振動」を端末のSecureStoreへ保存（開発用専用キー）。「振動を試す」を追加。ブラウザの設定は独立したlocalStorageで表示検証し、物理振動は実行しない。
- mobile/preview型・31テスト成功。ブラウザ1280/390/320幅の通常ホーム、スクロールを強制した小画面のCDPタッチ/縦110pxずれ、開始/終了、途中取消/復旧、設定保存を確認。Simulatorのイベントコールバックでも縦ずれ/親ロック/取消/再試行/撮影手順/終了/ハンドル開閉/保存値/振動API受理を確認。Simulatorは物理ジェスチャー/振動の検証ではない。
- 初回修正ではユーザーから「開始は進むが振動なし・終了は上下でリセット」との報告あり。追加修正で終了スライドが進むことはユーザー確認済み。振動なしは継続し、実機でAPI42回受理/エラーなし、設定オンを確認。低電力オフ・アクセシビリティのバイブレーションオンもユーザー確認済み。システムの触覚/Expo Go再起動を確認中。API受理は実際の振動の証拠としない。実写真・送信は架空のまま。

参照: [RN PanResponder](https://reactnative.dev/docs/panresponder)、[Expo Haptics](https://docs.expo.dev/versions/latest/sdk/haptics/)。iOSの低電力・システム設定・カメラ使用などで振動が抑制される場合がある。インストール済みexpo-hapticsのSwift実装も確認。依存追加/更新なし。

- モーダル全体の追従/途中復帰/下ドラッグで閉じる/ミニバー再展開、リボン中は親が横取りしないこと、内容が途中なら縦スクロールを優先することをSimulatorイベントとブラウザで検証。実機の最終追従確認は依頼中。
