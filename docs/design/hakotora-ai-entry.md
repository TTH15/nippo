# ハコ虎AIの入口と権限境界

2026年9月26日時点の判断。APIの現状は [API・権限一覧](../development/api-permissions.md) を参照する。

## 推奨する順番

1. Web/モバイル内の小さなAI画面で、日報の確認、シフト・車両の照会、要対応の要約など、現場で繰り返す読み取り操作から始める。
2. AIが呼ぶ業務ツールをサーバー側に少数定義し、既存APIと同じ認可・所属範囲で実行する。319個のHTTP操作をそのままモデルへ公開しない。
3. ツールの精度と監査ログを確かめてから、同じ業務ツールをMCPサーバー経由でChatGPT等へ提供する。外部連携用にユーザー単位のOAuth認証と権限取消を用意する。

MCPサーバーと専用UIは両立できる。OpenAIの現行Plugin構成はMCPサーバーのツールを中心とし、ChatGPT内UIは任意で追加できる。[MCPサーバーの公式説明](https://developers.openai.com/plugins/build/mcp-server)、[UI追加の公式説明](https://developers.openai.com/plugins/build/app-quickstart)。

## 最初の業務ツール候補

| ツール | 対象 | 必要な範囲 |
| --- | --- | --- |
| 今日の稼働と要対応を取得 | 自分の予定、未提出、駐車待ち | 本人はown、運営は対象領域のview |
| シフトを検索 | 日付・ドライバー・コース | own_view_shifts または can_view_shifts |
| 車両の状態を照会 | 稼働中・駐車済み・最終位置の鮮度 | can_view_vehicles と位置情報の別途運用条件 |
| 日報の未処理を集計 | 未提出・差戻し | can_view_reports |
| 希望休の提出案を作成 | 本人の希望休 | own_manage_shift_requests。確定前に本人へ内容を表示 |

書き込みは最初から自動実行せず、本人が内容を確認して確定する。配車変更、シフト確定、請求・給与、メンバー権限変更、GPS履歴や顔・免許・口座情報は、読み取りツールとしても個別の必要性と権限を確認してから追加する。

## 実装の境界

- ツールは会社IDを引数として信用せず、認証済みmembershipから解決する。対象IDも会社所属・本人所有をサーバーで検証する。
- 実効権限はDBの `role_capabilities` と `works_as_driver` を解決し、AIへの委任範囲との積集合で判定する。上位権限の含意は `expandCapabilities` を通す。
- ChatGPT等の外部接続にはユーザーごとのOAuth認証を使い、各ツールでトークンを検証する。[OpenAIの認証ガイド](https://developers.openai.com/plugins/build/auth)。
- ツール呼び出しの実行者、会社、対象、結果、確認操作を監査ログに残す。表示するデータは業務に必要な最小範囲へ絞る。
- 画面内AIとMCPで同じ業務ツール層を使う。UI/APIの都合で認可を二重実装しない。

## 公開前の判断

- 初期対象を運営者だけにするか、ドライバー本人にも提供するか。
- 外部MCPで扱う会社データ、画像、位置情報の範囲と保持・削除方針。
- 書き込み候補をどこまで許可し、誰の確認を必須にするか。
- 外部接続の配布対象、OAuth登録・失効、利用料金と監査ログの管理者。
