# 車両3Dモデル: Blender での仕上げ手順

2026-08-10 起票。Meshy.ai の生成結果を「地図・アプリに載る形」にするための手順。
**自動処理（`scripts/prepare-vehicle-glb.mjs`）でできることと、Blender でしかできないことを分ける。**

---

## 0. Meshy の「スマートトポロジー」を使う（2026-08-11 実測）

**入力は「スマートトポロジー」版を推す。** 実測（ホンダ アクティ）:

| | 通常の生成 | スマートトポロジー |
|---|---|---|
| 三角形 | 約200万 | **13,098** |
| ファイル | 34〜92MB | **0.23MB** |
| 面の並び | 写真由来のばらばらな三角形 | **整った網目** |

利点は3つ:

1. **削減が要らない**。200万→1.6万に潰すと形が甘くなり「粘土っぽさ」の原因になる
2. **Blender での面選択が効く**。L（リンク選択）やループ選択は整ったトポロジーでこそ機能する。
   写真由来のメッシュでは選択が破綻する
3. 軽い（0.23MB）

欠点: テクスチャが付かない（generate 段階）。ただし**こちらはどのみちテクスチャを捨てる**ので問題ない。
窓・タイヤは形状で分かる（窓は凹んだ面として作られている）。

## 1. なぜ Blender が要るのか

自動処理でできたこと:

- ポリゴン削減（200万 → 1.6万）
- 実寸化・原点を底面中心へ
- テクスチャの縮小／除去
- **ナンバープレート面の切り出し**（幾何条件で判定できるため）

**自動でできなかったこと: 窓・タイヤ・グリルの分離。**
テクスチャの明度から判定する実装を試したが、写真由来テクスチャの UV とサンプリングが噛み合わず、
**車体に黒い斑が散る**結果になった（レンダリングで確認・2026-08-10）。
形状からも判定できない（窓とボディは連続した面）。

→ **マテリアル分けは Blender で手作業**が確実。1台あたり15〜30分程度。

## 2. どのファイルを触るか

**Meshy からダウンロードした元の glb（texture 版）を触ってください。**
`apps/web/public/glb/Meshy_AI_*_texture.glb` に置いてあるもの。

- 整形後（`apps/web/public/models/*.glb`）は**テクスチャを捨てている**ので、
  どこが窓か目で見て分からない。作業には向かない
- 元ファイルはテクスチャ付きなので、**窓・タイヤ・グリルが見たまま**に分かる
- ポリゴンは200万あるが Blender なら扱える。重ければ先に Decimate してよい（次項2）

作業後の glb を `scripts/prepare-vehicle-glb.mjs` に通せば、実寸・原点・軽量化・
テクスチャ除去まで自動で付く。**Blender で付けたマテリアル名（glass / dark / plate）は保たれ、
色もそのまま**（`body` 相当だけ無彩色に整えられる）。

## 3. Blender での作業（1台ぶん）

1. **読み込み**: Meshy の **texture 版** glb を File > Import > glTF 2.0
2. **ポリゴン削減**（任意・スクリプトでもできる）: Modifier > Decimate > Collapse、Ratio を
   三角形が **1.5万〜3万**になるまで下げる。ドアの筋やバンパーの段差が消えない範囲で
3. **マテリアルを4つに分ける**（ここが本題）:
   | マテリアル名 | 対象 | 色の目安 |
   |---|---|---|
   | `body` | 車体外板 | 白〜薄グレー（**着色対象なので無彩色**） |
   | `glass` | フロント・サイド・リアの窓 | 濃いグレー（#2a2f36）・粗さ0.1 |
   | `dark` | タイヤ・グリル・バンパー下・ミラー | ほぼ黒（#15181c）・粗さ0.6 |
   | `plate` | 前後のナンバープレート | 黒（#111827）※自動処理でも作れる |
   - 選択のコツ: 編集モード → **面選択 → L（リンク選択）**や、
     UV/Image エディタでテクスチャを見ながら **選択 → Assign**
4. **書き出し**: File > Export > glTF 2.0（.glb）。
   - Include: Selected Objects のチェックは外す
   - Data > Mesh: **UVs / Normals は残す**（Tangents は不要）
   - Compression（Draco）は**オフ**（Mapbox の model レイヤーが読めない）
5. **仕上げ**: 書き出した glb を自動処理に通す
   ```
   node scripts/prepare-vehicle-glb.mjs <blenderから.glb> apps/web/public/models/<車種>.glb 3.4 16000 1024 flat
   ```
   → 実寸・原点・軽量化が揃う。マテリアル名（body / glass / dark / plate）はそのまま保たれる

## 4. アプリ側の扱い

- **着色は `body` だけ**に効かせる（`glass` / `dark` / `plate` は元の色を保つ）。
  地図（Mapbox）は `model-color` がモデル全体に掛かるため mix 強度を抑えている。
  three.js（車両編集のプレビュー・将来のモバイル）は**マテリアル名で選んで着色**できる
- マテリアル名は上表のとおりに揃えること。名前で判定している

## 5. 品質の目安

- 三角形 1.5万〜3万 / ファイル 300KB〜1MB（テクスチャなし）
- 窓が暗く、タイヤが黒く、車体だけが選んだ色になる
- 航空写真の駐車区画に置いたとき、区画に沿って収まって見える
