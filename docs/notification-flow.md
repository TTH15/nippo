# 通知フロー 設計叩き台

ステータス: ドラフト（合意形成中）／最終更新: 2026-06-21
基盤設計: `docs/platform-design.md`（テナント/identity/認証）。本書はその上の業務フロー。
関連方針: `構成A`（通知の生成・送信は Next.js API 側。Edge Function/Realtime不使用）。

---

## 0. 目的

ドライバーに**業務情報をプッシュ**する。代表例＝翌日アサイン通知:

> 「明日は〇〇コース／集合: △△／時間: 8:00／車は××に停まっています」

設計は変更通知・休み通知・手動連絡など他種別にも拡張できる形にする。

---

## 1. ★中心方針：LINEは各社持ち込み（BYO）＋アプリ内インボックスが真実

### 1-1. BYO-LINE（各orgが自前の公式アカウント）
- プラットフォーム共通の1アカウントではなく、**各 org が自社の LINE 公式アカウント（Messaging APIチャネル）を持ち込む**。
- **LINE料金は各社が LINE へ直接支払う**（無料200通／ライト¥5,000=5,000通／スタンダード等）。SaaS利用料とは分離。プラットフォームはLINE費用を抱えない。
- リッチメニュー・ブランディングは各社の公式アカウントのもの（各社が自由に運用）。プラットフォームは**導入支援をサービス化**可能。
- **identity設計への影響**: LINEのuserIdはチャネル別。よってLINE連携は identity グローバルでなく **`line_links(identity_id, org_id, line_user_id)` ＝ org別**。各orgのチャネル資格情報（token/secret）は暗号化してorg単位で保存。→ `platform-design.md` §2 を修正。

### 1-2. アプリ内インボックスを真実、LINE/pushは配信
```
通知レコード生成（受信者ごと・org/membership文脈）
  → アプリ内インボックスに必ず表示（= source of truth）
  → LINE連携済み: 各orgチャネル経由でLINEプッシュ
  → RNアプリ導入済み: push（後日）
```
- **LINE未連携でもアプリ内で必ず見える**（取りこぼし無し）。
- 運営画面に**LINE連携状況の一覧**を出し未連携を可視化＝催促可能。

---

## 2. 通知の種類（拡張前提）

| 種類 | タイミング | 優先 |
|---|---|---|
| 翌日アサイン通知（コース/集合/時刻/車両位置） | 前日夜（org可変） | ★まず実装 |
| 変更通知（【変更】アサイン/車両） | 変更発生時 | ★（柔軟性の要） |
| 手動ブロードキャスト（台風で休み等） | 即時 | ★ |
| 休み通知 | 前日夜 | org設定でON/OFF |
| 当日朝リマインダー / 締切リマインダー | 後 | 後 |

共通の「生成 → インボックス → 配信」パイプライン1本の上に種別を乗せる。

---

## 3. 送信トリガー（3モード＝柔軟性）

前日夜以降の変化（事故で車両不可・台風で休み等）に対応するため1種類にしない。

| モード | 例 | 仕組み |
|---|---|---|
| **定時バッチ** | 前日20:00「明日のアサイン」 | Vercel Cron → `/api/cron/daily-notifications`（cronシークレット保護、時刻はorg可変、JST） |
| **イベント駆動** | アサイン/車両変更で自動「【変更】」 | 既存イベントバス `src/server/events/bus.ts` に乗せる |
| **手動ブロードキャスト** | 「台風で本日休み」を運営が即送信 | 運営画面 → コース/全体へ |

- 定時送信後に変更が起きたら**黙って再送せず「【変更】」を追加**（インボックスに履歴が残る）。
- 冪等性: 「org×日×種別×membership」キーで定時バッチの二重送信を抑止（`notification_logs`）。

---

## 4. 対象者の決定

- 翌日 `shifts`（日付×コース→driver）に割当の **status='active' membership**。org単位でループ（テナント分離厳守）。
- identity/membership: 配信は **membership の line_link**（org文脈）。複数org所属ならアサインのある各org分を送る。

---

## 5. メッセージ組み立て（org単位CMS）

「何を通知するか」を **org×通知種別のテンプレート**で管理（CMS的）。

- プレースホルダ: `{コース}` `{集合}` `{時刻}` `{車両番号}` `{駐車位置}` `{氏名}` 等。
- org設定: 含める項目トグル（駐車位置を入れるか等）、通知種別ON/OFF、送信時刻、休み通知ON/OFF。
- 文面生成は**純粋ロジック（`core/logic`）**に置きWeb/RN/種別で再利用。
- 取得元: コース名/集合/時刻=`courses`、車両位置=最新駐車位置（§7依存）、車両=`vehicles`。
- 将来: リッチメニュー連携・セグメント配信（L Message的方向）。**初期はテンプレート＋トグルでstart**、フル機能は後。
- 置き場: `org_notification_settings` / `org_message_templates`（新設）。

---

## 6. 配信チャネル（生成と分離・アダプタ化）

| 時期 | チャネル | 必要なもの |
|---|---|---|
| 今 | LINEプッシュ | org別チャネル資格情報＋ membership の line_user_id（友だち追加で取得） |
| 後 | RN push（Expo/FCM） | 端末トークン |
| 常時 | アプリ内インボックス | なし（真実の置き場） |

生成結果を複数チャネルに流せるよう、チャネルは差し替え可能なアダプタにする。

---

## 7. 依存する未実装機能（無ければdegrade）

- **駐車位置キャプチャ**（QR/位置）→ 車両の最新位置。未取得なら位置行を省略。
- **翌日シフトのアサイン確定**。未確定なら送らない or 「未定」。
- **LINE連携（友だち追加）**。未連携ならアプリ内のみ（§1-2）。

---

## 8. エッジケース

| ケース | 挙動（案） |
|---|---|
| 翌日アサインなし | org設定で「休み通知」or 無通知 |
| 車両位置未取得 | 位置行を省いて送信 |
| LINE未連携 | アプリ内インボックスのみ＋運営画面で可視化 |
| 定時後の変更 | 【変更】通知を追加（再送でなく） |
| 送信失敗 | リトライ＋`notification_logs`に失敗記録 |
| 二重送信 | 冪等キー（org×日×種別×membership）で抑止 |

## 9. コスト整理

| 費用 | 誰が払う |
|---|---|
| プラットフォーム利用料 | 運営社 → あなた（エンタープライズ） |
| LINEメッセージ料 | 運営社 → **LINEに直接**（自社公式アカウント） |
| SMS OTP（認証） | プラットフォーム原価（利用料に内包） |

LINE導入支援は別途サービス化の余地。
