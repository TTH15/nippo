# 財務モデル（移転型台帳）設計叩き台

ステータス: ドラフト（合意形成中・**税理士レビュー前提**）／最終更新: 2026-06-21
基盤: `docs/platform-design.md`。連携: `billing-payroll-flow.md`(スコープ), `vehicle-session-flow.md`(QR/走行距離), `daily-report-flow.md`(集計)。
位置づけ: お金まわりの**背骨**。billing-payroll は org_id スコープのデルタ、本書は会計モデルそのものの再設計。

---

## 0. 大原則

1. **簡易だが"お金が消えない"**：移転型台帳（複式の整合性 × 単式のわかりやすさ）。簿記用語はUIに出さない。
2. **複雑になったら負け**：エンジン（台帳）は隠し、UIは給与明細/請求書/簡易P&Lだけ見せる。ドリルダウンは任意。
3. **全部 org 設定で柔軟に**：料率・手数料・上限・確定日・区分などは org が設定。
4. **自動だが上書き可・痕跡必須**：自動計算は"提案"。確定前に人が記録付きで調整できる（例: 事故入院でその月のリース免除）。

---

## 1. 核：移転型台帳（transfer ledger）

各エントリ＝「**どの勘定 → どの勘定へ、いくら、何の名目で**」の移転。
- 必ず出どころと行き先がある → **お金が消えない**（固定控除が利益に反映されない問題を構造的に解決）。
- UIは「誰が誰に何で払ったか」と**残高**だけ。借方/貸方・勘定科目は出さない。

例：日当¥10,000（会社→ドライバー）＋リース¥3,000（ドライバー→会社）→ ドライバー手取¥7,000、会社にリース収入¥3,000が自動計上。両側が見える。

---

## 2. 勘定・エントリ・区分・状態

**勘定（account）**: 会社 / 各ドライバー(membership) / 各取引先(元請け) / 外部(GS等)。

**エントリ**:
```
ledger_entry(
  id, org_id,
  from_account, to_account,        -- 勘定（種別＋id）
  amount,
  category,                        -- §下記
  occurred_on date,
  state,                           -- 'proposed'|'accrued'|'confirmed'(着金/振込)
  source,                          -- 由来: report/session/mileage/manual/rate
  source_ref,                      -- 元記録へのリンク（ドリルダウン）
  adjusted_from,                   -- 上書き元（修正エントリの場合）
  note,                            -- 調整理由（"入院"等）
  created_by, created_at
)
```

**区分(category)**: 売上 / 日当・歩合(payout) / リース / 事務手数料 / オイル(メンテ) / ガソリン / 前借り / 前借り手数料 / 最低保証 / 残業代 / 控除 / 調整。

**状態(state)**: proposed(自動提案) → accrued(発生確定) → confirmed(着金/振込で実現)。**会社利益は confirmed 分だけ実現**。

---

## 3. ★自動生成 → 確認 → 確定 ワークフロー

```
[自動生成] 日報・セッション・走行距離・料率から proposed エントリを生成
   ↓
[確認・調整] 運営が確認。例外は記録付きで上書き（adjusted_from + note）
   ↓ 例: 事故入院 → 月額リースを¥0/日割りに修正、note="入院"
[確定] 着金(請求書単位)→売上confirmed / 振込→payout confirmed
```
自動で大半が埋まり、例外だけ人が触り、痕跡が残る ＝ 自動化・柔軟・信頼の両立。

## 4. リース（日割り / 月額）

- 2モード（既存 `driver_leases` MONTHLY/DAILY）。コースごとに**日割りリース額**を設定（マスタに既定日割り額）。
- **日割り契約者**: 車両セッション(QR確定)の稼働日 × コース日割り額 → 「ドライバー→会社」エントリを自動生成。
- **月額契約者**: 毎月1回の固定エントリ（日割りは対象外）。
- **確定日も org 設定**。**按分/免除を記録付きで上書き可**（入院・休業等）。

---

## 5. オイル / メンテ課金

- **既定: ドライバーベースの走行距離累積**（毎日違う車でも逃げられない）。オドメーターOCR（チェックイン/アウト）から累積。
- **3,000km 跨ぐごとに**「ドライバー→会社」オイルエントリを自動生成（**日割り契約者**対象。閾値は org 設定）。
- **車種考慮**: EV等はオイル無し → 「走行距離ベースのメンテ課金」として一般化し、車種/org設定で有効/無効・内容を切替。
- 走行距離の帰属＝ドライバー（§論点で確定）。

---

## 6. ガソリン

- **基本ドライバー負担** → ドライバーの経費（会社↔は動かさない）。**領収書を添付して記録**（確定申告用、§8）。
- 会社が立替える運用がある場合のみ「会社→外部」＋「ドライバー→会社」エントリ（org設定）。

---

## 7. 前借り（advance）

- 「会社→ドライバー」(前借り)＋「ドライバー→会社」(手数料)。**ドライバー勘定の残高が月跨ぎで繰越**。
- **org 設定**: 手数料＝固定額/率、**残高上限**、回数制限など。柔軟かつ分かりやすい設定。

---

## 8. 確定申告補助・領収書管理（★ドライバー定着の価値）

- ドライバー勘定の**年間ロールアップ**：収入（payout）＋経費（ガソリン/オイル/リース等、本人負担分）。
- **領収書アップロード**（カテゴリ付き）。**経費区分は org 拡張可（後から追加）**。初期値=ガソリン/オイル/リース/その他。詳細は**税理士と詰める**。
- 目的: アプリ導入のドライバー側メリットを増やし現場定着（離脱防止）。
- インボイス制度・源泉等は税理士確認前提。

---

## 9. ドライバー勘定・請求書・着金/振込の消し込み

- ドライバー月次明細＝その勘定の当月エントリ ＋ 前借り繰越残高 → **会社が代理作成する請求書**。
- **着金は請求書単位**（元請け）→ その請求書に紐づくエントリを一括で confirmed へ。
- **振込**（会社→ドライバー）→ payout エントリを settled（消し込み）。銀行明細との照合。

---

## 10. UIの温度感（簿記を隠す）

- ドライバー: 給与明細（手取/控除内訳/前借り残高）＋確定申告サマリ。
- 運営: 簡易P&L（売上 確定/未確定・コスト・利益）＋請求書＋「未確定（着金待ち）」一覧。
- ドリルダウンは任意（数字タップで構成エントリ→元記録）。普段は見なくてよい。

---

## 11. org 設定（財務）一覧

リース日割り額(コース別)/既定日割り額・月額/日割りの確定日・前借り手数料/上限・オイル走行距離閾値と基準・車種別メンテ有効化・経費区分・着金/振込の確定運用。**柔軟かつ"わかる"設定UIが要件**。

---

## 12. 既存との関係（移行）

- 現 `Contribution`(集計) → **台帳エントリを自動生成**（売上/payout）。`ledger_entries`(3デルタ) と各経費テーブル(`driver_*_expenses`/`driver_leases`/`vehicle_recovery`)は**台帳に統合**。
- 利益は台帳から導出（confirmed基準）。既存の集計ロジックは活かしつつ背骨を台帳へ一本化。
- 段階移行（既存構造と並行 → 台帳をsource of truth化）。

---

## 13. テナント / identity

- 全エントリ org_id。勘定のドライバー＝membership（driver_id）。料率/設定は org 単位。
- 取引先(元請け)勘定＝当面 org内マスタ（`invoice_addresses`）。org→org の実台帳連携は将来（billing-payroll §4）。

---

## 14. 未確定・要確認（★税理士確認前提）

1. オイル走行距離の帰属＝ドライバー（確定）。EV/車種の扱いの詳細。
2. 前借りの手数料体系・上限の既定値（org設定だが初期推奨値）。
3. 月額リースの確定日・按分ルールの既定（入院等の例外運用）。
4. 経費区分の初期セットと拡張UI（税理士と確定）。
5. インボイス制度・源泉徴収・消費税の扱い（税理士）。
6. 簡易移転台帳 vs 本格複式の最終判断（既定=簡易移転台帳）。
