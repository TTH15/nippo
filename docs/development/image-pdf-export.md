# 画像・PDFエクスポートの共通方針

2026-09-01。シフト表・シフトメモ・日別配車で確認した実装と不具合対処を、他画面の出力にも使える形でまとめる。新規実装・改修ではここを参照する。共通化するのは方式の選び方と検証手順であり、既存の出力処理を一律に置き換えたという記録ではない。

## 既存実装と使い分け

| 対象・用途 | 現在の方式 | 再利用する点・制限 |
| --- | --- | --- |
| シフト表の半月PNG／PDF：固定レイアウトの帳票 | `ShiftPdfData` → 共通の `drawShiftTable` → CanvasでPNG／jsPDFでベクターPDF | データ・寸法・折返し・配置を共用。日本語フォントも揃える。画面DOMやhtml2canvasの文字計測に依存しない。現行帳票は日別の表示項目・契約絞り込みとは別仕様。 |
| シフトメモ：画面の任意範囲を切り出す | html2canvasで複製DOMを補正 → Canvasで日付・左列・親コース見出しを合成 → 同じPNGをPDFへ埋め込む | 固定列やスクロール位置を補正し、選択範囲に必要な見出しを補う。プレビュー・PNG・PDFの内容を共用。PDFの表は画像なので、ベクター文字にはならない。 |
| 日別配車：実際の一覧と同じ見た目で共有する | 実リストを複製 → プレート面をCanvas画像に置換 → html2canvasでPNG | 名前・コース札・契約区分・表示項目を引き継ぐ。文字計測のCSS補正あり。現在は幅408 CSS px・倍率3・最大10行ずつのPNGで、日別PDFは未実装。 |
| ナンバープレートなどCSS maskを含む部品 | 実部品を同じ幅で一時描画 → 計算済みCSSと同じSVG素材をCanvasへ描く | SVGの字形・寸法・配置・影を維持。画像化ライブラリのmask再現へ依存せず、通常の文字列や別フォントで代用しない。 |

新しい定型帳票はシフト表のように**出力データとレイアウトを分離し、PNG／PDFで共用する方式**をまず検討する。実画面の構造をそのまま保存する必要がある場合はDOM複製方式を選び、画像化で再現できない部品だけ差し替える。

PDF内の文字としての出力が必要か、見た目が同じ画像PDFでよいかを先に決める。PNGからPDFを作る方式では文字の欠けやずれもそのまま引き継ぐ。ベクターPDF方式では、PNGが正常でもPDFのフォント・配置を別に確認する。

## 容量の目安と圧縮

以下の容量・圧縮の詳細は開発者向け。軽配送業者が使う画面には、保存・共有に必要な操作だけを示し、小難しい仕組みの説明は載せない。

2026-09-01 ユーザー指定：この種のPDFは**通常、数百KB程度（目安1MB未満）**に抑える。文字の読みやすさ・元のPNG・帳票内容を優先し、容量だけを理由に解像度やJPEG品質を自動で落とさない。容量削減は出力処理側で行い、保存ボタンの容量表示や範囲縮小を促す案内は追加しない。これは厳密なファイルサイズ上限ではない。

jsPDFは `compress: true` と `putOnlyUsedFonts: true` を共通オプションで指定する。PNG埋込みでは `pngToPdf` を使い、`addImage` の `SLOW` 圧縮を明示する。これはPNGの画素を変えない圧縮で、JPEG品質の指定ではない。圧縮なしではPNGが一度展開され、RGB等の画素データがそのままPDFに入り、元PNGより数十倍大きくなる場合がある。

2026-09-01の実測（架空データ・9月前半15日、jsPDFの現行依存と本番描画コード）：

| 対象 | 圧縮前 | 圧縮後 | 画像・内容 |
| --- | ---: | ---: | --- |
| シフトメモ12枠 | 25,762,755 B（約25.8MB） | 671,220 B（約671KB） | 2660×3228px、全画素・ページ寸法を維持 |
| シフトメモ40枠 | 75,813,317 B（約75.8MB） | 2,092,668 B（約2.1MB） | 2660×9500px、全画素・ページ寸法を維持 |
| シフト表12人 | 412,925 B（約413KB） | 109,148 B（約109KB） | A4横・ベクター文字・同じ帳票描画 |

容量は開発時の検証値として記録する。シフトメモの保存ボタンは従来どおり「PDF」のみを表示し、1MB以上でも範囲縮小の案内は出さない。40枠のような大きな表を数百KBに保証する処理や、サイズ超過で保存を止める処理は入れていない。

PDFに埋め込まれた画像を取り出し、元PNGと全画素が一致することを確認した。12枠のメモと12人のシフト表は、圧縮前後のPDFをPopplerで描画した結果も全画素一致。`pdfExport.test.ts` は実際のjsPDFで、画素寸法・ページ寸法を維持したまま非圧縮に比べて小さくなることを検証する。フォントの登録時はTTF全体を読むが、現行jsPDFのIdentity-H出力は使用グリフをサブセット化するため、単に「日本語フォントを丸ごと埋めている」と決めつけない。

## 文字が下がる・欠ける場合の切り分け

通常の画面、生成されたPNG本体、PDFを分けて見る。モーダル内の縮小画像だけでは小さい欠けを見落とす。最初から通常画面のpaddingや文字サイズを変更したり、全テキストを数px上へ動かしたりしない。

### 日別配車で確認した原因：html2canvasの文字計測とCSSの干渉

確認環境は **html2canvas 1.4.1／Tailwind CSS 3**。html2canvasの `FontMetrics.parseMetrics` は元の `document.body` へ非表示の要素を置き、1×1画像の位置から文字のベースラインを測る。Tailwindの `img { display: block }` がその画像にも適用されると、改行後の位置で計測してしまう。結果として名前やコース札の文字が下がり、`overflow: hidden` の箇所では下側が欠けた。

`captureDispatchImage.ts` は、生成中だけ次の対象を `display: inline-block` に戻す。

```css
body > div[style*="visibility: hidden"] > img[width="1"][height="1"] {
  display: inline-block;
}
```

- 計測は**元document**で行われるため、`onclone` で複製側にCSSを追加するだけでは直らない。
- 対象は非表示の計測画像だけ。全画像のdisplay変更、通常一覧のレイアウト変更、プレート面の移動はしない。
- 一時CSSは呼出しごとに作成し、`finally` で成功・失敗とも撤去する。並行生成で他の呼出しのCSSを消さない。
- このセレクターはライブラリの内部構造に依存する。html2canvasやCSSの更新時には、計測コード・セレクター・PNG本体を再確認する。汎用CSSとして常設しない。

根拠となるローカル依存ソースは `node_modules/html2canvas/dist/lib/render/font-metrics.js`、`node_modules/html2canvas/dist/lib/render/canvas/canvas-renderer.js`、`node_modules/tailwindcss/src/css/preflight.css`。依存ライブラリ自体は直接編集しない。

### シフトメモで使っている補正とは分けて扱う

シフトメモでは2026-08-25に、`onclone` 内で名前札の行高・padding・表示方式を固定し、文字行を2px上へ、不足バッジの文字を3px上へ調整した。親コース見出しはCanvasで直接描き、通常画面は変えずに出力を整えた。

これらは**既存レイアウトで調整済みの個別値**で、すべての画像化に使う定数ではない。今回の日別配車の計測補正はシフトメモには追加していない。両方をそのまま重ねると文字が上へ寄る可能性があるため、今後共通関数へ移す場合は、まず固定オフセットを外した比較画像を作り、名前札・不足数・日付・見出し・スクロール後の出力を再検証する。過去の症状がすべて同じ根因だったとは断定しない。

## 出力処理で共通に確認すること

以下は新規・改修時の確認事項。既存の全方式が同じ実装になっているという意味ではない。

1. **内容を確定する。** 表示日・対象・絞り込み・段分け・表示項目・選択範囲・並び順を揃える。帳票側で仕様が違う場合は画面に明示し、見た目の修正に対象人数や保存処理の変更を混ぜない。非表示化を認可の代わりにしない。
2. **素材の準備を待つ。** フォントを明示的に読み込む場合は `FontFace.load()` 等の完了を待ち、使用フォントの `document.fonts.ready`、画像・SVGの読込や `decode()` を確認してから計測する。日本語・人名・数字のフォールバックを見落とさない。
3. **出力用の座標を固定する。** DOM方式では複製要素を使い、幅・背景・倍率を明示する。スクロールを原点へ戻し、sticky・transform・操作ボタン・選択枠の扱いを出力側だけで整える。通常画面を一時的に崩して撮影しない。
4. **非対応表現だけを置き換える。** CSS mask、影などは実部品と同じ素材・寸法・計算済み配置から描く。日別配車ではプレート面だけを置換し、外側の警告や番号未登録車の表示を残す。
5. **大きさを制御する。** CSS上の幅とPNGの画素数を区別し、縦に長い一覧は分割する。倍率を上げるだけで解決せず、想定する最大件数・折返し・端末で画素数と生成負荷を確認する。日別の10行分割を他帳票の万能な上限にはしない。
6. **見せた内容を保存する。** 画像PDF方式ではプレビューと同じ生成済みPNGをPDFへ埋め込む。日付や条件が変わったら古い画像を新しいファイル名で保存させない。遅れて完了した生成処理が現在のプレビューを上書きしないようにする。
7. **失敗と後始末を扱う。** 一時DOM・CSS・React root・Object URL等は所有元で片付ける。失敗時は誤った成果物を残さず、再試行できる状態へ戻す。共有中にURLを失効させない。
8. **生成と外部への保存を分ける。** 共有は生成済みFileを `canShare` で確認し、ユーザー操作から開始する。共有非対応・取消・失敗でも画像保存へ戻れるようにする。共有画面を閉じただけで「写真に保存済み」と表示しない。

## 検証の基準

| 確認対象 | 確認内容 |
| --- | --- |
| PNG本体 | 原寸で名前・漢字・数字・コース札・バッジ・見出し・プレートの上下位置、欠け、余白を確認。実画面とも比較する。 |
| PDF | 実ファイルを開き、ページ寸法・余白・文字の欠落・改ページを確認。ベクター方式はフォントも別に確認する。 |
| 境界条件 | 長い名前、複数コース、未設定、0件、未割当、警告、分割境界と2枚目以降、月またぎ、スクロール後、選択範囲の端。 |
| 操作 | 日付・絞り込み・表示項目変更後の再生成、連続切替、生成失敗・再試行、共有取消、旧画像の保存防止。 |
| 環境 | 実画面を使う隔離プレビューでPC・スマホ幅を確認。OSの共有先や写真保存は対象のiPhone／Android実機で別途確認し、未検証なら明記する。 |

単体テストでは対象範囲・分割・素材維持・CSSの適用範囲と撤去・生成結果の更新・エラー復帰を確認する。**html2canvasをモックしたテストや型チェックだけでは、文字位置が正しい証拠にならない。** 必ず実ブラウザで生成結果を目視する。

日別配車の既存テストは [captureDispatchImage.test.ts](../../apps/web/src/lib/captureDispatchImage.test.ts) と [ImageExportDialog.test.tsx](../../apps/web/src/lib/components/ImageExportDialog.test.tsx)。確認用の起動方法・モックの隔離条件は [preview-workflow.md](preview-workflow.md) を参照する。
