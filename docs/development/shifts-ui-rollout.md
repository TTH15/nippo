# 本番シフト画面への表示変更の移植

2026-08-31。ユーザーから「本番適用・デプロイ後もシフト画面が旧表示」と報告。
`cceca1e` には保存・会社境界の修繕とプレビューが含まれていたが、本番の `admin/(ops)/shifts/page.tsx` は旧「簡易／標準／詳細」のままだった。migration 155は保存用DB関数の追加であり、画面の変更を含まない。

## 今回の変更範囲

- **本番のシフトページ本体**を変更。年月・前後半を隣接させ、表示項目と軸を共通 `ShiftDisplayPanel` / `SmoothCollapse` 内に配置した。開閉状態はパネル内に保持し、開閉だけで表全体を再描画しない。
- シフト／車両／集合時刻を個別選択。旧 `shifts_view_density` の簡易・標準・詳細を読み替え、以後は `shifts_display_items` に保存する。認証キーは変更しない。全項目を隠しても稼働・未割当・希望休・競合の状態は残す。
- スマホは前後半を隠し、年月日pickerと前日／翌日で移動。月・半月の境界を越えられる。「全員／稼働／未割当」を維持する。シフトメモは従来の半月操作を残す。
- 車両非表示ではPCの単一コース行が約100pxから46pxになる。複数コース・便・競合表示など必要な情報に応じて高さは増える。コース軸は見出し・割当ドライバー名を常に残し、時間帯・車両・集合時刻を表示条件に合わせる。
- 日別画像は**同じ日別リストの描画**から作成。SVGのプレート面を実 `VehiclePlate` の座標・寸法で画像化し、かなと数字の間隔を維持する。オイル交換／使用不可の警告や番号未登録の車種表示は消さない。10件ずつ分割し、日付・対象の変更、PNGプレビュー、対応端末での共有、長押し・ダウンロード保存を用意した。
- 半月のPNG/PDFは従来の帳票形式・内容のままメニューに残す。使われていなかった旧DOM出力表は削除した。日別画像とは異なり、従来の帳票には表示項目の絞り込みを適用しない。

API呼出先・payload・権限・保存関数・実配車の空き判定・契約・料金計算・通知送信は今回変更していない。**追加migrationは不要**。155の実環境適用状況はユーザーの報告によるもので、この作業ではDB照合や再適用を行っていない。

## 実ページを使う隔離プレビュー

```sh
npm run preview:admin -- shifts --port 3191
```

[本番シフトUIのローカルプレビュー](http://127.0.0.1:3191/preview/shifts)。
`scripts/previews/shifts.tsx` が本番のページを直接importし、standaloneビルド時だけAPI・認証・権限・SWR・共同編集の依存を `shifts-services.tsx` の架空データに差し替える。レイアウトは既存 `AdminPreviewLayout` を再利用する。通常のNext公開ルートや認証は変更しない。

- 12人・未割当・番号未登録・オイル交換警告のサンプルを用意。コース割当・車両変更はメモリ内だけ保存し、再読み込みで戻る。「次の保存を失敗させる」でエラー表示を確認できる。
- 本番サービスの実装がバンドルに混入した場合はビルドを失敗させる。CSPで帳票用のlocalhostフォント1ファイル以外のfetchを禁止し、localhostの固定GET許可リストで外部・アプリAPIへのアクセスを遮断する。
- 設定変更・通知・AI読取・履歴・共同編集・本番の同時保存は検証対象外。旧 `/preview/driver-leases` は新しいリース／ラベル機能の設計確認用として別途維持する。

## 検証と再デプロイ

- 本番ページの表示切替・旧設定互換、画像生成失敗・共有キャンセル・条件変更時の古い画像の除外・複数ページ、警告／番号未登録車の維持を自動検証。
- TypeScriptとstandaloneビルド成功。Web全100ファイル941テスト成功（並列数2）。最初の全件並列実行では既存プレビュー1件が5秒制限に達したため、並列数を抑えて全件再実行した。テストのタイムアウト設定は変更していない。
- アプリ内ブラウザでPC1440px、スマホ390px／320pxの日付移動・表示設定・行高・日別3タブ・画像生成・ページ分割・警告／番号未登録車・半月PNG／PDF出力・セル編集・配車保存・エラー表示を確認。写真アプリへの保存はOS依存のため実機では未検証。実在データや本番通知を使った動作確認は行っていない。
- 今回のページ・共通部品・SVG描画ヘルパーを含む差分をコミットして再デプロイする必要がある。155の再適用やキャッシュ削除だけではUIは更新されない。この作業自体ではcommit/push・Vercelデプロイを行っていない。
