# 便を中心にした日報UIと画像入力

2026/10/17。隔離プレビューへ実装。本番未反映。DB・認証・計算式の変更はない。

## 日報設定と本人入力

- 運営は便ごとに「C1（午前）」「C2（午後）」のカードから、使う入力欄を選ぶ。同じ `ReportFieldInputs` を設定・本人の表示に共用する。
- 通常画面の選択肢はキャリアの入力欄グループ。「全便で使う」「項目ごとに指定」「このコースでは使わない」は詳細設定へまとめる。個別設定や複数グループの既存状態も保持し、勝手に午前/午後へ初期化しない。空の便は保存を止める。
- C1/C2の全体背景を青/紫に統一。本人も便名を主見出しにし、見出しで伝わる午前/午後を入力欄内で繰り返さない。複数グループの時は見出しを残す。

## 日報一覧

PCは「シフト」「提出された日報」を別の列へ分け、列見出しを表の先頭に一度だけ出す。本人名・車両/メーター・承認・送信時刻は1人1日でrowSpanを共有し、便の予定と提出実績を同じ行へ置く。対象外・却下の開閉、便別編集、承認を止める条件を保持する。

取得順がC2→C1でも、同一コース内は便番号順へ揃える。コース間の順位と車両/メーターの初期選択は保つ。未提出便・旧全体日報・シフト外・重複も同じ照合関数を使う。

## 画像の反映

- unit+fieldが複数コースにあれば先頭へ自動反映しない。候補を選ぶまでは確定不可。選択後も現在の入力欄に存在するコース・便・項目だけへ反映する。
- 複数シフト、入力済み、画像の再追加では確認を省かず、各項目の反映先と「入力済み値 → 読取値」を表示。チェックした項目だけを置き換え、他便・未選択項目を保持する。
- 同じ反映先に異なる値が重なる時は後勝ちで上書きしない。確認画面も重複を止める。読取値が同じ重複はcoreで1回だけ適用する。
- 読取の保存が成功してから数量を反映。読取中/保存中に日付やフォームが変わった古い結果を新しい画面へ入れない。反映せず閉じた場合も数量は維持する。
- 複数の別コースがある画像を最初のコースへ決め打ちして添付しない。確認した読取行には反映先フォームキーを記録する。原本・過去読取は削除しない。

## プレビュー

`npm run preview:admin -- admin --port 3199`

- 運営設定: `/preview/admin/courses?scenario=cycle-fields&role=admin` → 豊中 → 日報設定
- 本人入力: `/preview/admin/submit?scenario=cycles`
- 日報一覧: `/preview/admin/daily?scenario=multi-course&role=admin`
- 入力済み値の画像確認: `/preview/admin/submit?scenario=image-reupload`
- 同じ項目を持つ複数コース: `/preview/admin/submit?scenario=image-multi`

本番の `CourseReportFieldsEditor` / `SubmitPageClientV2` / `ReportCards` / `ReportSourceImageField` / `ReportImageReviewSheet` を再利用する。架空データとメモリ内保存のみ。cycles/image-reupload/image-multiの画像読取はrunner専用モジュールの固定値で、画像名にsecondを含めると2回目の値になる。他の画面のreaderは元実装へ委譲する。本番のOCRは置き換えない。
