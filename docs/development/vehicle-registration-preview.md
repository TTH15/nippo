# 車両登録・外観設定の確認手順

2026/09/14 実装。公開・本番DB更新は未実施。設計の経緯は [車検証からの車両登録と型式別3Dモデル](../design/vehicle-registration-and-models-2026-09.md)。

## 起動と画面

```sh
npm run preview:admin -- admin --port 3197 --mapbox
```

- 車両：`http://127.0.0.1:3197/preview/admin/vehicles?scenario=normal&role=admin`
- 地図：`http://127.0.0.1:3197/preview/admin/map?scenario=normal&role=admin`
- 地図を使わないときは `--mapbox` を省略できる。指定時もアプリAPI・認証・通知はfixtureに隔離され、地図タイル等だけMapboxへ接続する。
- 実画面の再利用元：`apps/web/src/app/(admin)/admin/(resource)/vehicles/page.tsx`。データは `scripts/previews/fixtures/vehicles.ts`。地図も本番ページと `fixtures/map.ts` を使用する。
- 色・外観・登録の保存はプレビュー内だけ。初期化で元に戻る。本番へ送信しない。

一覧のエブリイを開くとDA17Vの車体、前後のナンバー、コンパクトな色一覧を確認できる。「詳細設定」で外観の専用画面に移動し、車体全体・ボンネット・前バンパー・後ろバンパーを選んで色を変える。部位色は全体色を変えても残る。「個別色を解除」で全体色／元の材質へ戻す。車種の外観候補もこの画面で選ぶ。既存車は従来どおり自動保存、新規車は車両情報へ戻って保存する。

色は同一値を重複させず、無彩色を明るい順、有彩色を色相順に並べる。共通色と会社に追加した色を同じ規則で表示する。

## 型式とGLB

- `apps/web/src/lib/vehicleModelAssets.json` がアプリ側の版固定台帳。制作元は `~/Developer/assets/keivan-3d/catalog/roadmap.json` と各 `model/asset-manifest.json`。全20仕様は制作台帳で `in-progress`。制作元ファイルは変更していない。
- 元ファイル名とSHA-256を確認して取り込む。最大連番を自動採用しない。ハッシュが異なる版は取り込みを停止する。
- 型式は任意。保存値には接頭辞を保持し、照合時だけ全半角・英字大小・既知の排出ガス接頭辞を正規化する。未知の型式・メーカーの矛盾・「改」は外観を確定しない。
- 型式未確定の黒ボンネット写真仕様とアトレー候補は手動選択に限る。同じ型式の前後期や特装仕様まで自動識別するものではない。
- `appearance:<asset key>` だけを手動指定として扱う。旧来の汎用 `model_key` は型式照合を妨げない。メーカー／車種が違う手動指定は採用しない。
- N-VAN等の未収録モデルは代替表示と明示する。対応GLBが無くても車両登録できる。
- 1仕様ごとに全体・全体塗装・固定・灯火・ボンネット・前バンパー・後ろバンパー・プレート雛形の8ファイル、計160 GLB（約37.2 MB）。地図は表示対象だけを取得する。
- 位置は全分割片で共通。プレビューは子モデルを中心へ移し、親で回転する。ライトはGLBの灯火材質を発光させ、推測位置の光点を置かない。
- `scripts/lib/vehicle-plate-uv.mjs` で全体モデルと前後プレート雛形のUVを統一。プレビューは既存 `renderPlateImage` の字形を使用し、入力が揃った時点で実際の番号を描く。未入力に架空の番号は補わない。

```sh
node scripts/import-vehicle-models.mjs ~/Developer/assets/keivan-3d
node scripts/check-vehicle-models.mjs
```

幾何検査は接地・全長・有限座標・分割前後の三角形総数・変換行列・灯火面・塗装部位・前後プレートとUVを確認する。全仕様の全角度の造形品質を保証する検査ではない。

## 写真・PDFの読取

「新規追加 → 車検証を読み取る」で写真またはPDFを選ぶ。プレビュー限定の「写真例」「PDF例」「失敗例」から、架空書類を**実際の読取処理**へ渡せる。固定の抽出結果に置き換えるfixtureではない。

1. 元の書類を拡大して、候補値と見比べる。
2. 必要な欄を修正し、反映する項目だけチェックする。
3. 「選んだ項目を反映」で既存フォームに入力する。ナンバーが揃っていれば自社の登録済み車両を照会する。
4. 新規車は「保存」で登録。既存車は明示的な反映後に従来の自動保存が働く。

対象はナンバー4項目・メーカー・車種・型式・車検満了日の8項目。通称車種は車名と型式の対応表から提案する。住所・所有者・車台番号・検査時の走行距離は取り込まない。車台番号、初度検査年月、燃料／EVの読取と保存欄、公式JSON取込は今回の対象外。

- ブラウザ内でTesseract.js 7／PDF.js 6.3.289を使用。原本・全文をAPI、Storage、外部OCRへ送らず、ログにも残さない。原本は読取中のメモリと照合画面だけに置き、閉じると解放する。
- 日本語・英語の `tessdata_fast` は公開元のライセンスとハッシュを `apps/web/public/ocr/README.md` に記録。ライブラリ実行ファイルは `scripts/prepare-vehicle-reader.mjs` で固定版依存から生成し、Webのpredev/prebuildと隔離プレビュー起動で用意する。
- Worker、WASM、学習データ、PDF文字・CMap・フォントは同一オリジンで配信する。学習データだけブラウザキャッシュを利用する。
- PDFは先頭ページの文字抽出を優先し、不足時にOCR。表の左右列は単語の座標から行へ戻す。写真は独立欄の認識設定と明示DPIを使用し、Canvas化後の解像度自動推定で欄が落ちる問題を避ける。
- JPEG/PNG/WebP/PDF、15 MBまで、写真50メガピクセルまで。画像最大辺2800px、PDF最大辺2400px、120秒で中止。上限や方式は内部仕様であり、通常UIで技術説明は並べない。
- 未読欄は空欄。失敗・中止後は再選択／手入力へ戻れる。Worker、PDFタスク、Canvas、ImageBitmapを終了・解放する。
- 実書類の暗さ、傾き、反射、低解像度、複雑な多段表での読取精度は未検証。架空書類での成功を実車検証全般の精度保証とはしない。

## 部位色のDB変更と公開時の注意

`supabase/migrations/164_vehicle_part_colors.sql` は `vehicles.part_colors` と3部位の色制約を追加する。155の `save_vehicle_with_drivers` の会社範囲・ドライバー紐付けの競合検査・RPC権限は保ち、許可フィールドへ部位色だけを追加した。未適用DBではGETが従来列へフォールバックし、詳細画面の部位色を無効にする。

公開前に164の適用が必要。今回は開発DB・本番DBとも未適用。共有の外部開発DBへの試験は自動承認レビューに拒否されたため、実データ・ネットワーク・マウントを持たない一時PostgreSQLコンテナの最小スキーマで、実際の164と `scripts/db/tests/vehicle-part-colors.sql` をトランザクション内実行した。作成・更新・色保持・解除・他社拒否・不正色拒否・RPC権限・再適用が成功し、ロールバック後にコンテナを削除した。共有DB全体の移行確認の代用にはしない。

生成プレートはモデル版とナンバーのハッシュを含むパスへ保存・署名する。非同期生成中に旧型式／旧番号のGLBを返さない。旧パスからの移行時は既存車のプレートを `apps/web/src/scripts/backfill-plate-models.ts` で再生成する必要がある（今回は適用実行していない）。未生成時に古いプレートへフォールバックしないため、公開計画では再生成と署名先の切替を合わせて確認する。

## 今回の検証結果

- Web全体：129ファイル／1,197テスト成功。最終UIの本番用ビルド・TypeScript検査・tenant-scope検査・`git diff --check` 成功。
- 実GLB：20仕様／160ファイルの幾何検査成功。全20仕様のプレート雛形から架空番号の生成も確認。
- 車両プレビュー：PC 1280px／スマホ390pxの通常・0件・長い名前・大量・読込中・取得エラーを確認。横方向のはみ出しなし。adminは編集可、accounting/viewerは編集・読取入口なし。
- 3D：DA17Vの表示、昼夜、前後回転とナンバー、未収録N-VANの明示的な代替表示、外観詳細への移動、部位色、個別色解除、既存車の保存と再表示を確認。
- エラー：外観の保存失敗でも入力が残り、再保存ボタンで復帰。壊れたPDFから写真を選び直し、8項目の読取に復帰。未読欄の手入力、原本拡大・閉じる、読取中止の導線を確認。
- 読取：表形式の写真と文字PDFから大阪480り5678／スズキ／エブリイ／HBD-DA17V／2026年11月20日を取得。選択解除した車検満了日は反映せず、新規登録・同一ナンバーの重複案内を確認。
- 地図：1440pxの実Mapboxプレビューで型式別車体・塗装部位を表示。検証中に住所検索・一部地図タイルの一時的な通信失敗があり、全地図通信の無エラーは確認範囲外。車両管理プレビューの番号描画は端末内の共通画像処理、地図の非公開プレートStorageはfixtureなので、実Storageの署名・公開後の配信は未検証。
- 未検証：実機iOS/Androidのメモリ・カメラ選択、実書類の撮影条件別精度、全20仕様の全角度の外観、共有開発DB全体と本番の移行。これらを上記の架空データ検証に含めない。
