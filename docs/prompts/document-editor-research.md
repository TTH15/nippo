# 文書作成基盤(Docs-lite vs テンプレ差し込み)の外部リサーチ用プロンプト

ChatGPT / Claude 等にそのまま貼り付けて使う想定。リポジトリの中身を見せずに判断材料を集めるため、
前提情報はプロンプト内に自己完結で書いてある。回答を持ち帰ったら `docs/design/` に検討メモとして落とす。

---

## 貼り付け用プロンプト

```
あなたはWebフロントエンドと文書編集システム(リッチテキストエディタ・帳票・PDF生成)に詳しい
アーキテクトです。個人開発している業務SaaSに「文書作成機能」をどこまで内製するべきか、
技術選定と保守コストの観点から助言してください。

## 前提

- 開発体制: 個人開発(1人)。開発にはAIコーディングエージェントを併用。
- スタック: Next.js (App Router) + React 19 + TypeScript。Vercel運用。DBはSupabase(Postgres)。
- 利用者: 配送会社の社内数名〜数十名。日本語文書のみ。入力は日本語IME前提。
- すでに動いているもの(自前の「帳票エンジン」と呼んでいる):
  - React製のA4帳票コンポーネント(請求書)。固定レイアウトの帳票上で、金額・品目などの
    フィールドを直接インライン編集する(Word風のWYSIWYG。ただし自由文書ではなく定型帳票)。
  - 印刷は CSS の @media print、PDFは html2canvas + jsPDF(ラスタPDF・日本語フォント埋め込み)。
  - 過去に contenteditable/入力欄まわりで「コンポーネント定義位置によるフォーカス喪失・IME入力不能」
    などの地雷を踏んでおり、日本語WYSIWYGの難しさは体感している。

## やりたいこと

会社で必要な文書(請求書・契約書・雇用条件通知書・社内通知・月次レポートなど)を全部この
システム上で作成・管理できるようにしたい。理想を言えば「Google Docs / Word からマクロや
図形描画を除いたくらいの編集機能」だが、保守コストが見合わないなら諦めて、
「定型テンプレート + データ差し込み + 一部リッチテキスト欄」の路線に割り切ることも検討している。

## 聞きたいこと

1. リッチテキストエディタ基盤の比較: ProseMirror / Tiptap / Lexical / Slate (他に有力があれば追加)。
   特に (a) 日本語IMEの安定性の実績、(b) 学習コストと1人での保守性、(c) React 19 との相性、
   (d) ライセンスと商用利用、(e) Tiptap の無料版と有料Cloud機能の境界。
2. 「画面上でA4ページに分割表示しながら編集する」(Word型ページネーション)は、HTML/CSSベースで
   どこまで現実的か。Google Docs が canvas 描画に移行した経緯も踏まえ、
   ページネーションを諦めた場合のUX上の妥協点(編集は連続スクロール、ページ分割は印刷時のみ等)を整理してほしい。
3. 「フル自由編集のDocs-lite」と「テンプレート + 差し込み + 条項/段落単位のリッチテキスト欄」の
   2路線について、実装工数(人日)と年間保守コストの概算を、根拠付きで比較してほしい。
   契約書のような文書は実務上どちらで足りるかの見立ても。
4. PDF出力戦略の比較: 現行の html2canvas + jsPDF (ラスタ) / ブラウザの印刷→PDF /
   サーバーサイドChromium(Playwright/Puppeteer)印刷 / paged.js等のCSS組版ライブラリ。
   日本語テキストPDF(選択・検索可能)を出す場合の推奨構成と、Vercel上で動かす際の制約。
5. 総合推奨: 上記前提(1人保守・日本語・既存帳票エンジンあり)なら、どの構成をどの順で
   作るべきか。最初の2週間でやるPoCの内容と、「これが出たら撤退すべき」という危険信号も挙げてほしい。

## 回答形式

- エディタ基盤は比較表(観点×ライブラリ)で。
- 工数・保守コストは幅を持った概算でよいが、何を根拠にした幅かを明記。
- 最後に「私ならこうする」を1段落で。
```

## 使い方メモ

- 複数のAI(Claude / ChatGPT / Gemini 等)に同じプロンプトを投げて回答を突合すると偏りが減る。
- 回答のうち工数見積もりは楽観に寄りがちなので、「地雷(IME・undo・コピペ・ページネーション)を
  踏んだ場合の悲観シナリオも」と追撃質問すると良い。
- 結論が出たら: 採用路線を `docs/design/document-platform.md`(新規)に決定記録として残し、
  ~/Developer/docs/adr/ 行きにするかはその時に判断。
