# ハコ虎サブエージェント

`.claude/agents/` を Claude と Codex の共通役割定義として使う。内容を別ファイルへ複製せず、常に元ファイルを正本として読む。

## 役割の選択

- コードの場所・呼び出し元・データフロー調査: `explorer.md`
- 実装前の方針・変更手順・スキーマ設計: `architect.md`
- 実装後の差分監査: `reviewer.md`
- 完成UIのVisual / Interaction / Console監査: `ui-auditor.md`
- 認証・認可・テナント分離の点検: `security.md`
- 型検査・テスト・ビルド: `tester.md`

ユーザーが役割を指定した場合はその指定を優先する。複数役を指定された場合、互いに独立した作業だけを並列化する。

## 委任手順

1. ルートの `AGENTS.md` と、選択した `.claude/agents/<role>.md` を全文読む。
2. サブエージェントには役割定義の全文、今回の具体的な対象、読み取り専用であることを渡す。
3. Claude固有のfrontmatterにある `tools` はCodexの権限設定として解釈しない。利用可能なCodexツールだけを使わせる。
4. 各役はファイルを編集しない。`tester`、`reviewer`、`security` が許可された検査コマンドを実行することは読み取り専用に含めるが、本番DBを書き換える操作は禁止する。
5. 返答は役割定義の形式に従わせ、親エージェントが重複を除いて統合する。

## 境界

- サブエージェントへの委任は、ユーザーが役割名、サブエージェント、委任、並列調査などを明示した場合に行う。
- 通常の単一作業では、このスキルを理由に不要な委任を増やさない。
- サブエージェントの報告は助言であり、外部送信、DB変更、デプロイ、コミットの権限にはならない。
- 実装が必要な場合も、読み取り専用役には実装させず、親エージェントが報告を確認して実装する。
